# tests/ - Unit Test Suite

## Purpose

Hermetic unit tests for Quasarr, built exclusively on the standard-library `unittest` framework. Covers download-link extraction, search-source behavior, the userscript CAPTCHA routing, mirror filtering, download orchestration, notifications, SponsorsHelper helpers, release matching, and the SQLite layer.

## Ownership

`test_*.py` files in this folder and `data/filecrypt_fingerprint_vectors.json`, the synthetic cross-repository fingerprint contract fixture. `cli_tester.py` at the repo root is NOT part of this suite - it is a separate interactive/scriptable end-to-end client that exercises a RUNNING Quasarr instance over real HTTP against real configured sources; never confuse the two.

## Local Contracts

- Framework: stdlib `unittest` only - no pytest, no conftest, no coverage tooling, no test config in `pyproject.toml`. Classes are `<Subject>Tests(unittest.TestCase)`, files `test_*.py`, methods `test_*`, each file ends with an `if __name__ == "__main__": unittest.main()` block.
- Full-suite command: `uv run python -X utf8 -m unittest discover -s tests` (the `-X utf8` flag avoids Windows console encoding noise in log output).
- Tests must not perform network I/O or touch JDownloader. Patch in the consuming module's namespace (e.g. `quasarr.downloads.sources.<xx>.requests.Session`), not the `requests` library globally. Only the storage-layer tests (`test_sqlite_database.py`, `test_config_secret_decryption.py`, `test_config_atomic_writes.py`) touch disk, via `tempfile.TemporaryDirectory`.
- Synthetic-data rule (security-critical): source hostnames in tests are fake domains on the reserved `.invalid` TLD; use synthetic release titles (never paste real ones). Real public hoster/crypter domains are permitted only where the production matching logic keys on those literal domains - they are hoster/crypter services, not protected sources.
- `shared_state` is always faked (MagicMock with a `.values` dict, SimpleNamespace, or a small local class whose `values["config"]` is a callable returning dicts) - except the storage-layer tests above, which mutate the real module in `setUp`.
- `data/filecrypt_fingerprint_vectors.json` is the only shared data fixture: it contains synthetic `.invalid` URLs and full expected normalized URL/SHA-256 values, with no real hostname or credential. There is no shared test-helpers module; each file defines its own `FakeResponse`/`FakeSession`/fake shared_state inline.
- `test_crypter_candidates.py` pins SponsorsHelper-compatible credential/port/fragment/query normalization, full SHA-256 fingerprints, canonical enabled Filecrypt-only inventory, package-ID/link-index ordering, global fingerprint deduplication with every occurrence retained, frozen non-JSON-serializable records, and both fail-closed capacity sentinels: unique fingerprint 101 and occurrence 1001. The occurrence case deliberately repeats an already-known fingerprint, so only the occurrence bound can explain the sentinel, and a guarded resolver fails the test if any later link is inspected. It also pins that the inventory admits exactly what `helper_package_is_candidate()` admits.
- `test_crypter_sweep_records.py` pins the version-two decision codec against the approved spec: the constants, each state's exact key set (every single-key removal and every extra key is rejected, on both encode and decode), the member and live-offer key sets, 32/64-character lowercase-hex ID and fingerprint patterns, ascending unique members and retest members, the cohort bounds on both ends with `cohort_size` agreeing with the frozen list, closed result/instruction/mode/reason enums, non-negative non-boolean epochs, the exact one-window sweep deadline, and deterministic sorted URL-free round-trips. A cohort cooldown additionally requires complete terminal evidence: every member is `blocked`, has coherent tested/offer fields, replays only `hold`/`cooldown`, and exactly one member owns the `cooldown` response; pending, offered, unknown, or malformed members never project `cohort_size` as evidence. Robustness is proven by an unreadable-row table (bad JSON, wrong types, a lone surrogate, a 5000-digit integer literal that raises a plain `ValueError`, a 100,000-deep nesting built by string repetition that raises `RecursionError`, and schema versions 1/3/`2.0`/`True`), and the byte limit is proven by patching `MAXIMUM_COHORT_RECORD_BYTES` to exactly the encoded length and to one byte less. Encode-side surrogate sizing is forced at the JSON boundary to prove it raises a controlled `ValueError`/`OverflowError`, never raw `UnicodeEncodeError`. Expiry is pinned at deadline minus one, deadline, and deadline plus one for every state, including that an expired sweep is never decoded away. Migration is pinned to drop an old `observing` row at 1-4 observations, to preserve an old cooldown's exact retry deadline and surviving evidence count with a floor of one, to invent no cohort field, and to permit additive fields only on mappings without `schema_version`; v2/future hybrids never fall back to legacy. The service tests use a mutation-counting fake database with a deterministic before-mutation hook to prove that a valid version-two row projects into the existing snapshot keys with zero writes and a byte-identical row, that a legacy `observing` row keeps its current snapshot and is never promoted, that unsupported versioned hybrids self-heal instead of becoming active cooldowns, and that cleanup preserves/projects a concurrently installed valid v2 row after an invalid, expired-legacy, or future-version initial read.
- `test_crypter_cooldowns.py` pins the canonical protected-crypter resolver, import isolation, fixed three-distinct-observations/15-minute evidence rule, immutable duplicate evidence and provisional retry deadlines, first-surviving observation semantics, minimum cooldown, additive/malformed persistence handling across every service API, sanitized warnings, read-only snapshots, no-URL schema, state validation, and successful-access clearing. `test_deferred_protected_packages.py` pins the protected-package `deferred` schema, field preservation, the single provisional hold budget, read-only defer reads, the dynamic queue projection and status prefix, and database-only batch deletion including real-SQLite duplicate-row interleaving, per-ID verification, and zero JDownloader calls. `test_sqlite_database.py` separately proves real-SQLite read/write traces, deterministic concurrent mutation ordering, begin/callback/type rollback, committed delete/upsert semantics, exact one-row deletion, and nested Config/DataBase rejection.
- `test_crypter_block_settings.py` pins settings defaults/persistence, refresh-before-cache ordering, malformed-input preservation, authenticated route registration, the rendered Link Protection controls and `quasarrApiFetch` save boundary, the exact non-destructive fail-mode `/defer/` response, and the runtime block-mode gate itself: against real persisted cooldown plus package defer metadata it asserts that `fail` restores legacy capable selection, same-package link alternatives, and the plain CAPTCHA queue projection without building a `CrypterCooldownService`, that exclusions still apply, that unknown/missing modes defer, and that flipping the cached key in either direction changes behavior without touching the stored rows. It also pins that the capability - not the cooldown service - drives the canonical package ID contract: in `fail` mode a capable helper skips a non-canonical row (which no exclusion list can name) and receives the next valid package without any cooldown read, honors alphanumeric custom-category exclusions, while an incapable helper still receives that same row. Because `get_api()` installs its dict as the process-global shared state, `DashboardControlsTests` restores the previous `shared_state` values/lock.
- `test_deferred_packages_api.py` pins the Packages page deferred section and its commands: only queue rows whose projected `deferred.active` is true leave the ordinary queue, cards expose linkcrypter/reason/state/evidence/countdown/probe labels plus the manual CAPTCHA link but never a URL or hostname, every dynamic value in the deferred, queue, and history renderers is escaped, the AJAX fragment carries the same section, and the authenticated `POST /api/packages/deferred/probe` / `DELETE /api/packages/deferred` routes reject a non-list payload before delegation and otherwise return the atomic helpers' exact ordered per-ID results against real in-memory protected rows with zero JDownloader calls. It also pins that `fail` block mode makes probe inert (exact response, no `CrypterCooldownService`, byte-identical persisted defer metadata) while deletion still removes the row, and that the background refresh preserves the deferred selection: the snapshot/replace/restore order is extracted from the shipped `refreshContent()` by brace matching and replayed against a checkbox model parsed out of two real rendered fragments, so a missing, reordered, or retaining implementation fails on the resulting selection rather than on a string match.
  There is no JavaScript engine in the suite, so nothing here executes JS: that replay drives a Python checkbox model, and the shipped `restoreDeferredSelection` is pinned separately by `restore_selection_contract()`, which extracts the helper and requires exactly one parameter, `new Set(<that parameter>)`, a quoted-literal selector, a `<set>.has(<checkbox>.<prop>)`-guarded `checked = true` whose `<prop>` is the property `selectedDeferredPackageIds()` itself reads, exactly one `.checked =` write, and set/iteration/guard ordering. Eleven mutations of the shipped helper text prove those rules: the original eight cover empty/constant `Set`, a parameter disconnected from the set, `has(packageIds)`, wrong property, built selector, and unguarded or extra unguarded restore; three message-targeted mutants cover parameter count, `checked = true`, and operation order.
  Selector-injection safety covers both `querySelector` and `querySelectorAll`, reads each argument with quote and paren awareness, and requires every argument to be a quoted literal. It audits the static page, a real value-bearing deferred/ordinary/history fragment, and the composed page; a selector-hostile package ID is present in the rendered fragment but absent from every selector argument.
- `test_crypter_cooldown_statistics.py` drives the real routes, the real `CrypterCooldownService`, and a real SQLite file (one connection per table in a `TemporaryDirectory`) to pin the counter semantics: one observation per newly recorded distinct evidence and none for a duplicate package/fingerprint, exactly one `crypter_cooldowns` per entry into cooldown (including a second one after expiry, and none for further reports or a repeated blocked probe while cooling), and `crypter_probes` only where a queued probe was actually spent. The `deferred_packages` gauge is asserted as a live count over protected rows across hold, expiry, CLEAR, delete, repeated clears, and `fail` mode (which also leaves both stores byte-identical), and it is never a persisted row. Failure counters, `fail()`, and notifications are asserted untouched, and `build_solved_data` is pinned to the `name` key.
- Statistics outages are injected at the table handle (`RealDatabaseSharedState.statistics_unavailable()`, optionally writes-only) instead of being mocked away, which is what pins that a failing statistics table changes no defer response, no hold, no handout, and no probe, that the `crypter_events` ledger keeps the exact counts across the outage, a retry, a restart, and CLEAR, and that a read reports pending events without ever counting them twice. Two discriminators back this up: `rejecting_single_row_writes_to()` fails the test if any transition is recorded by a second `mutate_value` call outside its deciding transaction, and patching only `DataBase.retrieve` proves the flush is transactional - a competitor commits between a read and a write, so a read-then-write flush loses it while the real flush never calls `retrieve` for that key.
- Concurrency in the linkcrypter statistics is exercised against real SQLite with storage-seam hooks, not by mocking the unit: `flushing_from_another_connection_before()` runs a complete flush from a second connection just before a counter row is read (a two-read total then counts the same event twice), `flushing_from_another_connection_before_the_snapshot()` does it just before the snapshot transaction, `recording_single_row_reads()` fails if the ledger or any counter is read outside that snapshot at all, and `replacing_the_ledger_once()` commits a valid ledger row from another connection right before a cleanup, so an unconditional delete erases it. `recording_single_row_writes()` pins that an empty ledger keeps the statistics page write-free. Ledger robustness is table-driven over `MALFORMED_LEDGERS` (invalid JSON, non-objects, wrong keys, booleans, negatives, floats, strings, a 5000-digit integer literal that raises a plain `ValueError`, and a 100,000-deep nesting - built by string repetition so the fixture never recurses itself - that raises `RecursionError`, pinned as such by its own assertion so a changed interpreter fails there rather than silently weakening the self-heal proof), and `LEDGER_COUNT_CEILING` pins that counts stay exact far above 1,000,000 while a count that no longer fits fails the whole transition and leaves both rows untouched.
- Run the full suite after touching shared providers, download flow, search behavior, or notification logic. Per root change discipline, tests change only when the intended behavior in the covered area changed or the existing test is incorrect.

## Work Guidance

- Parameterized cases use `self.subTest(...)`; many simultaneous patches use `contextlib.ExitStack` or the parenthesized multi-context `with` form.
- Tests may reach into private underscore-prefixed helpers freely.
- Document behavioral intent with comments inside tests - explain WHY a rule/ordering exists (see `test_wx_direct_links.py`).
- Prefer exact-equality assertions on whole result shapes and on recorded request sequences.
