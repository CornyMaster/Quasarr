# tests/ - Unit Test Suite

## Purpose

Hermetic unit tests for Quasarr, built exclusively on the standard-library `unittest` framework. Covers download-link extraction, search-source behavior, the userscript CAPTCHA routing, mirror filtering, download orchestration, notifications, SponsorsHelper helpers, release matching, and the SQLite layer.

## Ownership

`test_*.py` files in this folder and `data/filecrypt_fingerprint_vectors.json`, the synthetic cross-repository fingerprint contract fixture. `cli_tester.py` at the repo root is NOT part of this suite - it is a separate interactive/scriptable end-to-end client that exercises a RUNNING Quasarr instance over real HTTP against real configured sources; never confuse the two.

## Local Contracts

- Framework: stdlib `unittest` only - no pytest, no conftest, no coverage tooling, no test config in `pyproject.toml`. Classes are `<Subject>Tests(unittest.TestCase)`, files `test_*.py`, methods `test_*`, each file ends with an `if __name__ == "__main__": unittest.main()` block.
- Full-suite command: `uv run python -X utf8 -m unittest discover -s tests` (the `-X utf8` flag avoids Windows console encoding noise in log output).
- Tests must not perform network I/O or touch JDownloader. Patch in the consuming module's namespace (e.g. `quasarr.downloads.sources.<xx>.requests.Session`), not the `requests` library globally. Only the storage-layer tests (`test_sqlite_database.py`, `test_crypter_sweep_transitions.py`, `test_crypter_cooldown_statistics.py`, `test_config_secret_decryption.py`, `test_config_atomic_writes.py`) touch disk, via `tempfile.TemporaryDirectory`.
- Synthetic-data rule (security-critical): source hostnames in tests are fake domains on the reserved `.invalid` TLD; use synthetic release titles (never paste real ones). Real public hoster/crypter domains are permitted only where the production matching logic keys on those literal domains - they are hoster/crypter services, not protected sources.
- `shared_state` is always faked (MagicMock with a `.values` dict, SimpleNamespace, or a small local class whose `values["config"]` is a callable returning dicts) - except the storage-layer tests above, which mutate the real module in `setUp`.
- `data/filecrypt_fingerprint_vectors.json` is the only shared data fixture: it contains synthetic `.invalid` URLs and full expected normalized URL/SHA-256 values, with no real hostname or credential. There is no shared test-helpers module; each file defines its own `FakeResponse`/`FakeSession`/fake shared_state inline.

The occurrence case deliberately repeats an already-known fingerprint, so only the occurrence bound can explain the sentinel, and a guarded resolver fails the test if any later link is inspected. It also pins that the inventory admits exactly what `helper_package_is_candidate()` admits.
- `test_crypter_sweep_records.py` pins the version-two decision codec against the approved spec: the constants, each state's exact key set (every single-key removal and every extra key is rejected, on both encode and decode), the member and live-offer key sets, 32/64-character lowercase-hex ID and fingerprint patterns, ascending unique members and retest members, the cohort bounds on both ends with `cohort_size` agreeing with the frozen list, closed result/instruction/mode/reason enums, non-negative non-boolean epochs, the exact one-window sweep deadline, and deterministic sorted URL-free round-trips. Robustness is proven by an unreadable-row table (bad JSON, wrong types, a lone surrogate, a 5000-digit integer literal that raises a plain `ValueError`, a 100,000-deep nesting built by string repetition that raises `RecursionError`, and schema versions 1/3/`2.0`/`True`), and the byte limit is proven by patching `MAXIMUM_COHORT_RECORD_BYTES` to exactly the encoded length and to one byte less. Encode-side surrogate sizing is forced at the JSON boundary to prove it raises a controlled `ValueError`/`OverflowError`, never raw `UnicodeEncodeError`. Expiry is pinned at deadline minus one, deadline, and deadline plus one for every state, including that an expired sweep is never decoded away. Migration is pinned to drop an old `observing` row at 1-4 observations, to preserve an old cooldown's exact retry deadline and surviving evidence count with a floor of one, to invent no cohort field, and to permit additive fields only on mappings without `schema_version`; v2/future hybrids never fall back to legacy. The service tests use a mutation-counting fake database with a deterministic before-mutation hook to prove that a valid version-two row projects into the existing snapshot keys with zero writes and a byte-identical row, that a legacy `observing` row keeps its current snapshot and is never promoted, that unsupported versioned hybrids self-heal instead of becoming active cooldowns, and that cleanup preserves/projects a concurrently installed valid v2 row after an invalid, expired-legacy, or future-version initial read. Self-heal-on-read is table-driven and splits the two cases deliberately: the four genuinely unreadable rows each warn exactly once, while a structurally valid record whose own window merely ended is deleted silently, because a clean expiry is not a discarded row.

Real SQLite additionally proves the committed cohort, its holds, and its ledger survive reopening, and that two threads never lose a member result. Because real fingerprints are hash-ordered, every real-database test resolves the offered member's owning package from the inventory instead of assuming one.

- `test_sponsors_helper_terminal_confirmation.py` owns the three terminal routes. It pins the byte-compatible legacy bodies; one uniform exact v2 envelope and 400/409/503 mapping; structured HTTP-200 retry bodies; JDownloader reconciliation after a lost submitted write with exactly one `add_links`; cleanup and completion crash windows; complete replay; and exact-once failed history, notifications, download/decryption counters, and disable state. A structured success is impossible while the protected package is still present or the disabled flag is unproven. Concurrency is deterministic and needs no sleep: `SideEffectGate` parks the first request inside the one irreversible step (`add_links`, `fail()`, the protected disable write) and a second identical request is started behind it, so a duplicate transition sets the gate's second event and is asserted directly; a serialized one can never reach it. Provenance is covered per route by `seed_operation(...)`, which persists the record a crashed request would have left (`not_started`, `attempting`, or the seven-key legacy row) and returns its evidence: a crash before the effect must still submit/fail/disable next to a stale unmarked failed row, JDownloader package or disabled flag, and a crash after it may only reconcile from the artifact carrying that evidence. Crash-injection cases count operation-table transactions, which are `begin`, the durable attempt, `mark_submitted`, `mark_complete`. `MemoryTable.events` records access order, which is what distinguishes "decided from history" from "verified its own write" when the two answers otherwise agree.
- Task 6 projection coverage spans `test_crypter_cooldown_statistics.py` and `test_deferred_packages_api.py`: statistics expose only fixed sweep/progress/deadline/cooldown/retest/individual and terminal-state fields, while deferred cards render sanitized tested/total/deadline/retest values only for a projected cohort and never expose a sweep ID, operation ID, fingerprint, URL, or hostname. Hostile projection values are rejected before interpolation. The countdown contract is the same static-then-replay pattern as the selection restore: `countdown_epoch_contract()` requires exactly one `dataset.cohortDeadlineEpoch ?? dataset.retryAfterEpoch` read, on one element binding, inside a one-parameter helper the updater calls without reading a dataset itself, and each shipped-text mutant of that read is asserted to be rejected. The replay parses the real rendered elements and re-evaluates the same fallback over several ticks, so a cohort card that carries only its own deadline is proven to keep counting down.
- Run the full suite after touching shared providers, download flow, search behavior, or notification logic. Per root change discipline, tests change only when the intended behavior in the covered area changed or the existing test is incorrect.

## Work Guidance

- Parameterized cases use `self.subTest(...)`; many simultaneous patches use `contextlib.ExitStack` or the parenthesized multi-context `with` form.
- Tests may reach into private underscore-prefixed helpers freely.
- Document behavioral intent with comments inside tests - explain WHY a rule/ordering exists (see `test_wx_direct_links.py`).
- Prefer exact-equality assertions on whole result shapes and on recorded request sequences.
