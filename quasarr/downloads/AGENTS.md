# quasarr/downloads/ - Download Side

## Purpose

Receives a grab request from the SABnzbd-emulating API, picks the matching source module, extracts hoster/crypter links, classifies them, and either pushes plain links to JDownloader's linkgrabber, auto-decrypts hide-crypter containers, or parks protected links for the userscript-based CAPTCHA UI. Also renders the merged JDownloader + DB package state back as a SABnzbd queue/history.

## Ownership

- `__init__.py` - orchestrator: source selection, link classification, package IDs, the `submit_final_download_urls()` funnel, `fail()` bookkeeping
- `mirror_filters.py` - canonical mirror-token normalization and the final pre-JDownloader whitelist filter
- `packages/` - SABnzbd-shaped queue/history aggregation, archive/extraction tracking, auto-start, deletion, deferred-linkcrypter projection
- `sources/` and `linkcrypters/` - see Child DOX Index

## Local Contracts

- `download()` candidate order: (1) the `source_key` from the search payload (trusted), (2) every registered source whose configured hostname is a substring of the URL, (3) raw-crypter fallback when the URL itself matches a crypter pattern. The first source returning non-empty links wins.
- Link classification priority is direct > auto > protected (`AUTO_DECRYPT_PATTERNS`/`PROTECTED_PATTERNS` in constants, the magic mirror label `junkies`, or a source result explicitly marked `protected: true`). If any direct links exist, crypted fallbacks are ignored. Failed auto-decrypts are demoted into the protected bucket.
- `resolve_protected_crypter_key(link)` is the canonical classification-derived resolver for cooldown policy: it accepts existing `[url, mirror]` entries, returns only protected `detect_crypter()` keys or the `junkies` mirror-tag key, and rejects auto-decrypt, direct, source-key, and malformed values. `protected_crypter_keys()` is the matching allowlist, and `classify_links()` consumes the resolver so these contracts cannot drift.
- A hide.cx container the crypter itself reports as missing is TERMINAL, not a fallback candidate. `unhide_links()` takes an optional `outcome` dict and sets `{"gone": True}` on HTTP 404 from either API call (the foreign `/fc/Container/<id>` resolve or the `containers/<id>` fetch) - hide.cx's explicit "container not found or invalid". A 5xx, an unreadable body, or an unexpected shape is NOT marked, because a human may still win those. `decrypt_links_if_hide()` answers `status="gone"` only when EVERY container it tried was reported missing, `handle_auto_decrypt_links()` turns that into `container_gone: True`, and `process_links()` calls `fail()` instead of extending `classified["protected"]`. Parking such a package would put it in the CAPTCHA queue forever: the helper only takes Filecrypt, and no person can solve a container the crypter cannot find. Both 404 branches log at INFO with the status, because the operator otherwise sees only "Could not decrypt any links" and has to guess.
- A terminal grab failure logs its reason at ERROR and its successful failed-package persistence at WARN; failure to persist that state logs at ERROR.
- `process_links()` honors the filecrypt kill switch right after `classify_links()`: `_drop_filecrypt_if_disabled()` reads the cached `shared_state.values["filecrypt_enabled"]` (default `True`, set by `storage/setup/filecrypt.py`) and, when `False`, strips filecrypt links out of the protected bucket so the package fails cleanly if nothing else remains. `classify_links()` itself stays pure/shared_state-free; only the orchestrator applies the flag.
- `process_links()` is also the single place a package's origin is recorded. Each of the three priority branches calls `_record_origin(shared_state, package_id, crypter, links)` with its OWN bucket right before its handler, so the stored crypter names the branch that actually won rather than the first link of a mixed result: `"direct"`, `"hide"`, and for protected links `resolve_protected_crypter_key(classified["protected"][0]) or "unknown"`. `providers/package_origin.record_package_origin()` is create-only, which is what makes the auto-decrypt fallback safe: when auto-decrypt fails, the existing code appends `classified["auto"]` to `classified["protected"]` and falls through, and the protected branch's second write is a no-op that leaves the first branch's crypter and `added_epoch` intact. The counterpart prune lives in `packages/delete_package()` (only when `success`) and in `packages/delete_database_packages()` (per accepted ID) - nothing else removes an origin row, because it deliberately outlives the protected blob.
- `packages._protected_origin(links)` answers the crypter key and bare host of a still-protected package from its own stored links - the same two values `/captcha` derives for its "Crypter · Mirror · Links" line. `_collect_packages()` calls it in the protected branch only (linkgrabber/downloader rows get `("", "")`) and puts the pair on the queue item as `crypter`/`mirror`, which `api/packages/carbon.py` prefers over the stored `package_origin` row. That is what lets packages grabbed BEFORE the origin table existed still fill those columns, with no backfill and no stored value that can go stale. Crypter resolution is two-step and deliberately NOT just `resolve_protected_crypter_key()`: that function answers COOLDOWN eligibility (filecrypt/tolink/keeplinks/junkies) and rejects `hide`, which lands in the protected queue whenever auto-decryption failed and the grab fell back to a manual CAPTCHA. Such a package is still a Hide package and `/captcha` names it one, so the mirror-tag resolver runs first (it owns the junkies key, which comes from the tag rather than the URL) and `detect_crypter()` - which knows the auto family too - decides otherwise. It returns `("", "")` only when NEITHER resolves: the Downloads contract's exception covers the host of a LINKCRYPTER, and an unrecognized link could be a hoster or a source, so publishing its host would widen the exception into what the contract forbids. Lazy-imports `quasarr.downloads` for the same circularity reason as `_lifecycle_deferred_by_package()`.
- Package IDs are deterministic: `Quasarr_{category}_{32-hex-hash}` validated by `PACKAGE_ID_PATTERN`; the category segment is lowercase alphanumeric (`[a-z0-9]+`), matching what `add_download_category()` accepts, so custom categories like `movies4k` produce valid IDs. `package_id_exists()` checks the protected DB, failed DB, and JDownloader before any download.
- `submit_final_download_urls()` is the ONLY path that hands direct links to JDownloader (also imported by `api/captcha` and `api/sponsors_helper`). It applies the download-category mirror whitelist through the side-effect-free `project_final_download_urls()`; if a whitelist drops everything, the default `phase="all"` persists the package as failed itself, while `phase="submit"` persists nothing and returns `{"success": False, "mirror_rejected": True, "reason": ...}` - a terminal caller owns when its failure lands, and persisting it here would count it, announce it and drop the protected package before any of that could be bound to an operation. `phase="all"` otherwise keeps every existing caller's full submission/cleanup semantics, while `phase="submit"` stops immediately after a successful JDownloader handoff so the terminal route can durably mark `submitted` before cleanup.
- `jdownloader_holds_operation(shared_state, package_id, terminal_operation)` is the crash-window reconciliation check for an interrupted terminal download. It searches the exact `submission_comment(package_id, terminal_operation)` string in the `comment` field of linkgrabber packages/links and downloader packages/links, in that order; `True` proves *this* operation submitted, `False` permits a retry after a proven failed handoff, and `None` means device state is unavailable and never permits another `addLinks`. A bare package-ID comment - what every legacy, automatic and manual submission carries - deliberately proves nothing, because an earlier life of the same release leaves exactly that. `failed_package_records_operation()` is the same rule for failed history: only the `terminal_operation` marker stored with the row answers, a missing or unreadable row is `False`, and only an unreadable store is `None`. `failed_package_reason()` reads back the reason *this* operation recorded, which is the only place it survives (the operation record stays bounded and secret-free) and is what lets an interrupted failure finish telling the operator. `finalize_protected_removal()` deletes then reads back the protected row and reports both confirmed absence and whether this call performed the removal, which gates solved notification and counters exactly once. A failed-history cleanup uses the same proof with solved notification disabled.
- `failed_row_value(title, reason, terminal_operation=None)` is the one projection of a failed-history row, so the legacy path and the terminal transaction write identical bytes and only the marker differs. `commit_terminal_failure(service, ...)` is the terminal path's only way to persist a failure: it hands `TerminalOperationService.record_failure()` the `failed` target, that value, and the `statistics` counters `failed_downloads` + `failed_decryptions_automatic`, which all commit with the operation's own marker in one transaction. Table names and counter names live here because this package owns the shape of the row; when they may be written lives in the provider.
- `download_package(..., comment=None)` defaults the JDownloader comment to the package ID, which is the identity the package projection reads. `submit_final_download_urls(..., terminal_operation=...)` is the only caller that extends it, through `submission_comment()`; `quasarr/downloads/packages` therefore resolves every comment through `package_comment_id()` (`decode_submission_comment()`) before `is_quasarr_package()`, so a marked package keeps its ID, category, status and auto-start.
- Protected-package JSON owns the tracked notification references for that release; no separate notification table exists. `submit_final_download_urls(..., remove_protected=True)` captures this context before deletion, edits the original notification on solved/failed outcomes, and accepts `notification_details` so manual and SponsorsHelper solutions render accurately.
- `store_protected_links()` creates the protected row through one `mutate_value()` transaction that re-reads the current value: duplicate detection happens earlier, so a concurrent grab can create and defer the same package in between. An existing readable row wins field by field and only genuinely missing keys are added, which is what keeps `deferred` (and its one-hold marker) alive; an absent or unreadable row is replaced by the fresh blob.
- A deferred linkcrypter package stays a protected queue item and is never written to `failed` automatically. `get_packages()` projects `deferred` details per package by merging the stored `deferred` block (owned by `providers/crypter_cooldowns.py`) with `crypter_projection()`'s coherent snapshot/decision pair, one row read per linkcrypter, so an expired provisional hold, a superseding crypter cooldown, or a hold whose sweep generation is gone is reflected without rewriting package metadata and a transition between two reads can never be projected half-applied. Only the rendered `filename` changes: `DEFERRED_STATUS_PREFIX` replaces `PROTECTED_STATUS_PREFIX` while the hold is active; ID, category, and `type="protected"` stay unchanged, and packages without defer metadata never read cooldown state. The projected `deferred.active` boolean is the Packages UI's sole deferred-section gate; the UI must not infer an active hold from persisted metadata alone, and it renders no `sweep_id` or `link_fingerprint`. In `fail` block mode (`crypter_blocks_deferred()` is false) `get_packages()` builds no `CrypterCooldownService`, projects no `deferred` key, and renders every protected package with the normal CAPTCHA prefix; the stored metadata is untouched, so switching back to `defer` restores the held projection without a restart.
- A package with no active legacy hold additionally falls through to `_lifecycle_deferred_by_package()`, which calls `FilecryptLifecycleService.project_deferred_holds()` (reading `filecrypt_link_states` exactly once for the whole request, never once per package) to project any `held`/`blacklisting` lifecycle link onto its owning package(s) in the same legacy-shaped `deferred` dict - the `filecrypt_link_lifecycle_v1` generation never writes `PACKAGE_DEFER_KEY`, so without this fallback a helper that only negotiates that capability leaves every accepted block invisible on this page. An active legacy hold on a package always wins unchanged; the lifecycle projection is consulted only when the legacy one is absent or inactive, and is gated by the same `crypter_blocks_deferred()` switch as the legacy path so `fail` mode stays a pure bypass for both. Its `state` is the raw lifecycle state (`held`/`blacklisting`) and `hold_type` is always `crypter_cooldown` (so both renderers' existing "Cooldown" label applies); it never carries a real `evidence_count` or cohort sweep progress, since the lifecycle model tracks neither - those fields stay at 0 rather than fabricate a number.
- `delete_database_packages(shared_state, package_ids, expected_type="protected")` is the batch counterpart of `delete_package()` for packages already proven to be database-only: it issues no JDownloader call. Shape rejections (`invalid_package_id`, `duplicate`) are decided up front; state is never prevalidated. Each remaining ID is removed by `delete_deferred_package()`, whose transaction re-reads the row and yields `not_found` or `not_deferred` when the package vanished, was cleared, or was replaced meanwhile, so a replacement row is reported instead of deleted. Failed cleanup runs only after that protected predicate succeeds and uses `DataBase.delete_exact()` on the captured value, removing at most one matching preexisting row while preserving later same-key rows. Verification failures are `delete_failed`. It returns `{"deleted": [...], "rejected": [{"package_id", "reason"}]}` in input order. The Packages API passes only the submitted selected IDs and delegates all per-ID validation and conditional deletion to this helper.
- `fail()` is the legacy, non-terminal bookkeeping path and takes no operation: it stores the row FIRST and only counts `failed_downloads` and logs the WARN once that store landed, so a broken store can never leave a counter answering for history nobody has. Its shape stays `{"success", "title", "failed": True}` so the *arr client records the grab and can blocklist it, but `success` now reports whether the failure was really persisted rather than always `True`.
- `packages/` auto-start moves exactly ONE Quasarr package per call from linkgrabber to the download list; archive packages are only "finished" when extraction completed; `nzo_id` is the Quasarr package ID read from the JD `comment` field (JD uuid fallback for foreign packages).
- `packages.get_packages_for_device(shared_state, device, *, auto_start=True)` is the device-isolated entry point: it builds one request-scoped `JDPackageCache(device)` and routes every query/cleanup/auto-start call through that same `device`, never `shared_state.get_device()`. Legacy `get_packages(shared_state, _cache=None, auto_start=True)` keeps its public behavior and delegates to it after resolving its device through `shared_state.get_device()` (or reusing a caller-supplied `_cache`, as `delete_package()` does). Both share one internal `_collect_packages(shared_state, cache, get_active_device, auto_start)` body, so the aggregation logic itself never forks between the two callers.
- Sources call `mark_hostname_issue(initials, "download", msg)` on errors; the orchestrator clears the issue when a source returns usable links.

### Mirror-Selection Policy

Product-wide policy - do not redesign it; per-source specifics live in the Per-Source Notes of `quasarr/downloads/sources/AGENTS.md`.

- HARD RULE: Quasarr never verifies whether a direct hoster link is online and never fetches a hoster URL to probe liveness. Resolving and verifying hoster links is JDownloader's job (paid, hoster-specific handling Quasarr cannot and should not replicate). Never add a tier that fetches a direct hoster URL to test it.
- Selection picks the best link set from the source's own signals only. Tier 1: online-certified crypted container, cheapest crypter first - a green hide container (auto-resolves, no CAPTCHA) before a green filecrypt container (may cost a CAPTCHA). Tier 2: direct links carrying a green signal - best effort only, because the signal really certifies the container. Tier 3 (last resort): the first offline-flagged mirror, so the release still fails cleanly into the blacklist-and-retry path.
- If a source exposes no online signal at all: newest mirror first (when recency is known), then first/arbitrary mirror.
- A link that turns out dead is not a selection bug; it is absorbed by the *arr blacklist-and-retry flow. Rationale (measured on WX): direct links agree with their container ~95% of the time; the trade is deliberate - an online download that costs a CAPTCHA beats a fast download that is dead.
- A human manually clicking a still-online link will always beat the automated choice for a single release; that is not a signal Quasarr can generalize from and not a reason to start probing links.

## Work Guidance

- Link entries are lists, not tuples: `[url, mirror]` with an optional third `state_url` element (a missing `state_url` counts as online).
- Per-source mirror-name normalization is duplicated on purpose (each site labels hosters differently); the canonical global mapping lives in `mirror_filters.py` + `constants.MIRROR_TOKEN_ALIASES`.
