# quasarr/providers/ - Shared Services

## Purpose

The shared-services layer consumed by every other subsystem: cross-process state and the My.JDownloader device lifecycle, web server, logging, auth, per-source sessions, notifications, metadata lookups, statistics, Cloudflare/FlareSolverr helpers, HTML templating, and generic utils.

## Ownership

- `shared_state.py` - process-shared singleton (`set_state()` per process) and the JD device lifecycle (`get_device`, `run_device_request`, `set_device_settings`)
- `web_server.py` - WSGI wrapper; `serve_forever()` for the API, `serve_temporarily()` + `temp_server_success` flag for setup wizards
- `log.py` - loguru wrapper; context emoji from the caller's module name via `_context_replace`; per-context levels via `LOG`/`LOG_<CONTEXT>` env vars
- `auth.py` - route auth modes (`public_endpoint`/`require_api_key`/browser default), Bottle auth hook, startup audit; owns the login page (`_render_login_page`) and Basic-auth challenge (`require_basic_auth`), both dispatched Classic/Carbon via `page_dispatch.render_page` with lazy in-function imports (avoids the `auth -> page_dispatch -> static_assets -> auth` cycle). The login page's Carbon branch composes its own standalone `.cds-auth`/`.cds-auth__card` document (brand mark above a centred 400px sign-in card, `carbon_templates` component helpers plus a direct lazy `asset_url` import) rather than delegating to `render_carbon_simple_page`, since that shared shell cannot place content both above and below its single content-plus-footer card. Unlike the Basic-auth 401 challenge, the login footer always shows a working Classic UI link (`/ui/classic`) even while unauthenticated.
- `myjd_api.py` - vendored, modified My.JDownloader client (MIT, third-party) - keep modifications minimal
- `jd_cache.py` - `JDPackageCache`, valid for exactly one `get_packages()`/`delete_package()` call, never reused across requests. Every query goes through `_query(label, call, default)`, which counts the API call and answers `default` whenever the device cannot: the MyJD errors, an `AttributeError` from a `shared_state` holding a device NAME rather than a connected client, a `TypeError` from `query_packages()`/`query_links()` answering `False` instead of a list, and any non-list answer where a list is expected. The cache is read while rendering the Downloads page, the dashboard queue tile and `GET /api/packages/list`, so an unusable device must degrade to "nothing known" rather than propagate
- `imdb_metadata.py` / `xem_metadata.py` - cached metadata chains: IMDb IDs resolve basic title/year/poster and title searches through the local Radarr or Sonarr client; localized titles use locale-specific IMDb release-info HTML and preserve that cache across Arr refreshes; German localized titles are transliterated once at this provider boundary for every source; `get_localized_title` takes an optional caller `deadline`, rechecked at each gate because the Arr refresh between them costs its own request, and then answers from cache only; direct HTML and the 60s FlareSolverr fallback clamp to both that explicit deadline and the active search-worker budget, and the fallback is skipped when either is spent; TheXEM supplies season names
- `radarr_api.py` / `sonarr_api.py` - minimal clients cached in shared_state via `set_client`/`get_client`; IMDb and free-title lookup, IMDb→TMDB/TVDB resolution (`get_tmdb_id`/`get_tvdb_id`), plus library-feed seeds `get_wanted_imdb_ids` / `get_wanted_episodes` (wanted = missing + cutoff-unmet, missing first, capped at the passed `limit`, paging past filtered entries and stopping at an optional caller `deadline` and the active worker budget. Every page request uses the lower of the client's own timeout, the caller's remaining timeout, and the worker allowance. `client.wanted()` returns `None` on a failed request so paging does not read it as the last page, and an optional `status` dict reports whether the walk completed, which callers persisting progress need; the movie helper skips not-yet-released titles and the episode helper skips not-yet-aired ones). All return safe empties when the client is unconfigured.
- `statistics.py` - DB-backed counters, constructed inline at call sites; also projects the derived `deferred_packages` gauge, fixed-cardinality Filecrypt decision state, and terminal-operation counts
- `version.py` - `__version__`, the single source of version truth
- `obfuscated.py` - generated obfuscated userscripts; consumed only by `api/captcha`; regenerated only through the private Quasarr-UserScripts generator repo
- `cloudflare.py` - challenge detection, thread-safe process-local 24-hour per-netloc FlareSolverr gating, lazy per-operation browser sessions, response wrappers, and get/post/session helpers
- `html_templates.py` / `html_images.py` - UI page shell, base64 image constants, and language-flag emoji/SVG fallback assets for setup UI. `render_success`/`render_success_no_wait`/`render_fail` each dispatch Classic/Carbon via `page_dispatch.render_page`; the Classic branch is the original body unchanged (byte-identical), the Carbon branch is a lazy-imported `carbon_templates` closure. `render_error_page(status_code, message=None, *, title=None)` is the generic 401/403/404 (and "package not found") entry point: sets `response.status`, closed to `{401, 403, 404}`, Carbon branch delegates to `carbon_templates.render_carbon_error_page`
- `hostname_issues.py` - DB-backed source health tracker (`mark_/clear_/get_hostname_issue`)
- `crypter_cooldowns.py` - shared linkcrypter cooldown state machine; validates canonical protected-crypter keys, atomically records independent evidence, owns protected-package defer metadata and its generation binding, and exposes read-only availability snapshots
- `crypter_candidates.py` - pure bounded Filecrypt candidate inventory and the cross-repository normalized URL fingerprint contract; frozen occurrences retain decoded links only transiently; also provides the unbounded `enumerate_filecrypt_lifecycle_candidates()` used by the lifecycle path (never truncates, always `oversized=False`)
- `filecrypt_lifecycle.py` - pure, Quasarr-import-free lifecycle record codecs: table-name constants, `MINIMUM_SWEEP_SIZE=2`, `MINIMUM_GLOBAL_COOLDOWN_SIZE=5`, strict `schema_version=1` encode/decode for link-state (`held`/`blacklisting`/`blacklisted`), sweep-header (`sweeping`/`healthy`/`cooldown`), sweep-member, offer-receipt, and migration-marker records; `link_state_is_held(record, now)` / `link_state_is_recheck_eligible(record, now)` deadline predicates. Decoders are total (return `None` for any malformed, oversized, recursive, wrong-version, or incoherent input); encoders raise `TypeError`/`ValueError`. `decode_link_state()` is clock-free; `decode_sweep_header()` accepts `now=None` for API compatibility but does not prune on read. Per-row byte limit (`_MAX_LIFECYCLE_RECORD_BYTES = 16 KiB`) never bounds row count. Boolean values never satisfy integer fields (`type(v) is int` guards). Package IDs are validated against the canonical `Quasarr_[a-z0-9]+_[a-f0-9]{32}` pattern (mirrored from `quasarr.constants.PACKAGE_ID_PATTERN` without importing it). The `response` field in offer receipts is caller-owned and treated as an opaque dict by this codec; it MUST contain only the normalized identifier/count/state decision contract, never URLs, titles, raw exception text, or secrets. The `cooldown` sweep-header state additionally requires `sweep_deadline_epoch > 0` (strictly positive; epoch 0 is rejected by both encoder and decoder). The `blacklisting` link-state record persists the full recheck offer identity (both `recheck_sweep_id` and `recheck_offer_id`) to allow `confirm_blacklist()` to build an immutable receipt and exact replay response.
- `filecrypt_lifecycle_service.py` - `FilecryptLifecycleService`: opening, leasing, read projections, first-time outcome recording, retest/probe outcome recording, blacklist confirmation, and receipt pruning for the Filecrypt link-lifecycle. Constants: `FILECRYPT_LINK_LIFECYCLE_CAPABILITY="filecrypt_link_lifecycle_v1"`, `FILECRYPT_CRYPTER="filecrypt"`, `DEFAULT_SWEEP_WINDOW_MINUTES=15`, `OFFER_LEASE_SECONDS=300`, `RECEIPT_ADVISORY_THRESHOLD=4096`, `MAXIMUM_HELD_SECONDS_BEFORE_BLACKLIST=7*24*3600`. The lease must outlast the helper's worst-case browser solve of one container - a report that arrives after it expires is answered `stale` and thrown away, so the whole solve is wasted and retried; `crypter_sweeps.OFFER_LEASE_SECONDS` is the same value and the two are pinned equal. `prune_receipts()` enumerates all `filecrypt_offer_receipts` rows, decodes with `decode_offer_receipt()`, treats `expires_epoch <= int(clock())` as expired, emits a count-only advisory warning when total >= `RECEIPT_ADVISORY_THRESHOLD` and a separate count-only warning for malformed rows, then calls one unlimited `mutate_values()` sorted by key; callback deletes only when current raw bytes exactly equal the enumerated expired raw and still decode as expired at the captured `now` (concurrent replacements are preserved); returns count of rows changed to `None`; storage failure propagates. Constructor accepts `shared_state`, `clock=time.time`, and `identifier_factory` (default `secrets.token_hex(16)`). `prepare_offer(protected_rows, *, excluded_package_ids=(), preferred_fingerprint=None)` returns `None` or an offer dict with `capability/mode/crypter/sweep_id/offer_id/link_fingerprint/deadline_epoch/occurrence`; mode is `sweep/individual/retest/probe`. Sorting: candidates by fingerprint ascending, occurrences by `(package_id, link_index)`. All writes for one opening/lease are one atomic `mutate_values` call; callback is side-effect-free and does no storage reads/enumeration. Fail-closed on malformed persisted header/link state/member row; stale generation member rows removed atomically on new opening. `decision()` projects the sweep-state header to `available/sweeping/healthy/cooldown/unavailable`. `project_link(fingerprint)` projects a link-state row to `available/held/retest/blacklisting/blacklisted/unavailable`. `active_blacklisted_fingerprints()` returns ascending tuple of final-blacklisted fingerprints only (explicitly sorted, never relying on DB order). Sweep window from `shared_state.values.get("filecrypt_sweep_window_minutes", 15)`, valid 1..1440, else 15. Sweep opening includes link-state targets for every proposed first-time fingerprint; the callback aborts if any is non-None (valid or malformed). Singleton individual opening includes the sweep-state header as a read-only target; the callback aborts if a live valid or malformed non-None header is present. If no first-time member has a non-excluded handable occurrence no sweep is opened and `mutate_values` is never called. Individual generation binding lives in the offered sweep-member row; the report's `sweep_id` must match the member's `generation_id`. `record_blocked(report, protected_rows)` and `record_access(report, protected_rows)` accept first-time outcomes: one atomic six-target `mutate_values` (header, member, link-state, receipt, protected, outbox). Return `{**response, terminal_required: False, fingerprint, package_id, terminal_operation_id}` or `None` (stale). Receipt stores only the response dict. Replay checks receipt `generation_id == report.sweep_id`. CLEAR always responds with `state=healthy, cleared=True, accepted="", sweep_tested=0, sweep_total=0` and a positive deadline; the persisted header may remain sweeping with `global_possible=False`. Header derivation: `None` → individual; malformed non-None → stale; live sweeping matching generation → sweep; live sweeping mismatched → stale; live healthy/cooldown → stale; expired valid → individual. Hold `retry_after_epoch` is always report acceptance time + configured cooldown (24h), never offer or sweep deadline. A BLOCKED report on a live retest lease whose own hold has already expired always changes durable state, never a no-op: with no live cooldown header it transitions `held` -> `blacklisting` (terminal), and under a live cooldown header - the race where a fresh fully blocked sweep re-armed the sweep-wide cooldown between the offer and the report - it clears the spent lease, backs the link's own `retry_after_epoch` off to report time + cooldown, writes a `retest`/`blocked` receipt, and answers the header's live `cooldown`/`crypter_cooldown` with no counter movement. Answering `stale` there would leave the link held with an expired deadline, so the next `prepare_offer()` would lease it again and a permanently dead link could be offered without bound. `MAXIMUM_HELD_SECONDS_BEFORE_BLACKLIST` closes that loop: once `now - first_blocked_epoch` reaches it, such a retest retires the link instead of backing it off, which bounds the retest offers one dead link can consume. All response deadlines are strictly positive; `tested<=total` always holds; state/instruction/hold_type pairings enforce: hold cannot pair cooldown, cooldown requires crypter_cooldown, sweeping/individual cannot pair crypter_cooldown.
- `filecrypt_lifecycle_decisions.py` - pure report normalization and response validation/builders. No clock, storage, or config reads. `normalize_lifecycle_blocked_report(report)`/`normalize_lifecycle_access_report(report)` validate exact key sets, `crypter=="filecrypt"`, `protocol_version` is exact non-boolean int 2, canonical IDs, and `terminal_operation_id == terminal_operation_id(package_id)`. `validate_defer_response(response)` enforces: exact 9-key set, `tested<=total`, deadline>0, retry>0, and coherent state pairings (hold cannot pair cooldown state; cooldown instruction requires cooldown state + crypter_cooldown hold_type; sweeping/individual cannot pair crypter_cooldown). `validate_access_response(response)` enforces: exact 7-key set, `tested<=total`, deadline>0, `cleared=True` requires `state='healthy'`, `state='cooldown'` allowed only for `cleared=False,accepted='unknown'`. `BLACKLIST_RESPONSE_KEYS` is a frozenset of the 9 exact keys for a blacklist response. `validate_blacklist_response(response)` enforces: exact 9-key set matching `BLACKLIST_RESPONSE_KEYS`, `instruction=='blacklist'`, `state=='individual'`, `hold_type=='none'`, all counters (evidence_count, retry_after_epoch, sweep_tested, sweep_total) exactly 0 and non-bool, `sweep_deadline_epoch` strictly positive non-bool, `sweep_id` 32 lowercase hex. `build_lifecycle_defer_decision(...)`, `build_lifecycle_access_decision(...)`, and `build_blacklist_decision(*, sweep_id, sweep_deadline_epoch)` construct and validate their respective responses. `validate_blacklist_response` is separate from `validate_defer_response` until route rendering and the shared helper contract explicitly add blacklist.
- `crypter_sweeps.py` - pure version-two linkcrypter decision codec: constants, strict record encode/decode, lazy legacy migration, the fixed read-only decision projection, and the shared helper-package candidate predicate
- `terminal_operations.py` - durable SponsorsHelper terminal-operation identity, exact record codec with three-shape migration and non-persisted `legacy_unproven` provenance, capacity/pruning, phase transitions, the retirement of a complete record whose package returned, the atomic failure/counter commit and notification pending phase, per-operation artifact evidence, the JDownloader submission-comment codec, and identifier-free state counts
- `utils.py` - grab-bag: payload generate/parse, category resolvers, title matching (including shared date-numbering parsing/query/match/canonicalization), online-status checks, `download_package` (the JD linkgrabber submission)
- `ui_preference.py` - UI mode source of truth (`carbon`/`classic`) and precedence resolver: env -> query -> cookie -> cached shared-state -> default. `DEFAULT_UI = "carbon"` - Carbon is the shipped default; Classic remains fully reachable through every precedence tier above it (`QUASARR_UI` env, `?ui=classic` query, the `/ui/classic` cookie route, and a persisted global preference via `POST /api/ui-preference`), and Carbon falls back to Classic automatically if its assets are missing or a render raises. `load_ui_preference()` performs one storage read attempt, falls back to default on retrieval/validation failure with sanitized class-only warning, then performs exactly one cache update. `persist_ui_preference()` rejects non-string/invalid values with `ValueError` before any DB construction and performs one `update_store` followed by one cache update.
- `page_dispatch.py` - central page renderer selection: classic path executes outside Carbon fallback handling; Carbon path snapshots Bottle response immediately before asset/import/render work; missing assets and ordinary Carbon exceptions restore snapshot then fall back once; raised `HTTPError`/`HTTPResponse` pass through unchanged; CSP is applied only after successful Carbon render (global response for string body, returned `HTTPResponse` headers otherwise).
- `carbon_icons.py` - closed Carbon icon map and renderer for shell/components. Icons are sourced from the current upstream `packages/icons/src/svg/32` SVG files and stored as reviewed path/polygon/rect constants with source URL + SHA-256 metadata; no runtime SVG fetch, no arbitrary icon names, and no raw SVG input from callers.
- `carbon_templates.py` - Carbon shell/component contract: escaped scalar boundaries, closed token validation for page/tone/kind/input/class tokens, and full-document shell renderer (`render_carbon_html`) with fixed nav/header/modal/toast landmarks, API-key meta safety, and structural guards rejecting inline handlers/scripts, remote resources, duplicate IDs, and unsafe `target="_blank"` anchors. `TableColumn`/`data_table` are generic table primitives that shipped ahead of a caller; no shipped page still calls them since the Dashboard and Statistics pages that once did were rebuilt on their own custom-column markup, but both stay public (`__all__`) and unit-tested rather than removed. `protected_captcha_count(shared_state)` is the shared shell-chrome helper for the header CAPTCHA badge count (live `protected` DB queue size, defaulting to 0 on a read failure); every Carbon view needing that count - not just Statistics - calls this instead of keeping a private copy, and a swallowed read failure logs only the exception class, never its text (which could carry a hostname). `render_carbon_html()` builds one `badge_html` fragment (`<span class="cds-header__badge">`, present only when the count is above zero) and reuses it verbatim for both the header bell overlay and the side-nav "CAPTCHA" link label - a count is not one of the four allowed `.cds-tag` uses (categories/capabilities/history-result/custom-recommended-Default markers), so it never borrows that component. `.cds-header__badge` itself carries only the badge's look (red `#da1e28` fill, size, radius); ## Local Contracts

- Each process calls `shared_state.set_state(dict, lock)` before use; read `shared_state.values[key]`, write `shared_state.update(key, value)`. `values["config"]`/`["database"]` hold the classes, not instances.
- All JDownloader access goes through `shared_state.get_device()` (blocks and retries forever with escalating backoff) or `run_device_request(name, fn, default)` (one reconnect+retry then the default on JD request errors - but its first attempt calls `get_device()` internally, so it too blocks until a device is connected). `TokenExpiredException`/`RequestTimeoutException`/`MYJDException` from `myjd_api` are the canonical JD error set.
- `generate_download_link` and `parse_payload` must stay in sync: urlsafe-base64 of exactly 6 pipe-separated fields (`title|url|size_mb|password|imdb_id|source_key`). This is the bridge between search results and the `/download/` endpoint.
- Auth: after `add_auth_hook`, every route defaults to browser auth; exceptions are marked with the decorators; `audit_route_auth_modes` raises at startup for unguarded API-prefixed routes; the API key lives in `Config('API')`.
- FlareSolverr: always check `utils.is_flaresolverr_available(shared_state)` first; when a FlareSolverr solution returns a userAgent, update shared_state `user_agent` globally.
- Optional Cloudflare fallback uses `LazyFlareSolverrSession`: an uncached netloc tries plain HTTP first; a real 403 or recognized challenge gates that netloc process-locally for 24 hours, after which same-host requests skip plain HTTP and go directly through FlareSolverr until the monotonic TTL expires. Gate access is thread-safe, first detection logs once at DEBUG, and cached requests stay quiet. Browser sessions remain lazy, are reused within one search/feed/download operation, and close from an outer `finally`. A solve asks for the standard session timeout rather than the caller's shorter search timeout, but the clamp still caps it at the time the worker budget has left - the session timeout is the requested amount, never a guaranteed minimum. Solved JSON endpoints may arrive inside a browser-rendered `<pre>` wrapper, which `FlareSolverrResponse.json()` unwraps.
- Search-facing provider request helpers resolve `checkpoint()` / `clamp_timeout()` lazily inside their functions so providers do not create a module-import cycle back through `quasarr.search`. Cloudflare plain requests, solves, retries, and session creation; IMDb HTML/fallback requests; and Radarr/Sonarr requests all refuse a spent worker budget and clamp at the final network boundary. Every timeout a stage needs is resolved before that stage's `try`, so a refusal propagates to the source as `SearchBudgetExhausted` instead of being logged as a request failure. `flaresolverr_destroy_session` is deliberately not gated: destroying an already-created browser is required cleanup after exhaustion and keeps its existing session timeout.
- IMDb metadata must not depend on an unofficial metadata API or GraphQL. Basic metadata comes from local Arr lookup responses. A localized title is guaranteed by accepting an Arr alternate title with an explicit matching ISO language code, the Arr `originalTitle` (or `title` when Sonarr omits it) when the record's `originalLanguage` names the requested language, a country-matched AKA row from IMDb release-info HTML or embedded page data, or IMDb `titleText` only when embedded request context proves the requested language, full localization, and disabled original-title preference. Arr lookups are checked before IMDb HTML; the HTML path serves English from the unprefixed default release-info path because IMDb 404s on `/en/`. Unproven `titleText` and instance-localized Arr display titles are not localized-title fallbacks. If no authoritative localized source exists, the lookup logs an error and returns no title. The cache preserves sanitized localized metadata, while `get_localized_title` returns one source-facing form: German umlauts and sharp S are transliterated on every successful return path, so individual sources must not add retries for spelling variants. Movie categories resolve stale or missing base metadata only through Radarr; TV categories resolve it only through Sonarr.
- DB tables owned here: `sessions`, `hostname_issues`, `imdb_metadata`, `imdb_searches`, `xem_all_names`, `xem_season_names`, `statistics`, `crypter_cooldowns`, `crypter_events`, `sponsors_helper_terminal_operations`.
- Filecrypt candidate inventory accepts protected DB `(package_id, json_string)` rows, sorts canonical `PACKAGE_ID_PATTERN` packages by ID and stored link index, skips packages `helper_package_is_candidate()` rejects, and includes only links resolved by `resolve_protected_crypter_key(link) == "filecrypt"`. Full lowercase SHA-256 fingerprints deduplicate candidates globally while retaining every occurrence. Both capacity limits fail closed with the same empty `oversized=True` sentinel, returned immediately on discovery of unique fingerprint `MAXIMUM_COHORT_SIZE + 1` or occurrence `MAXIMUM_COHORT_OCCURRENCES + 1` and before any later link is inspected: truncating occurrences would leave a denominator that still looks complete. Raw links remain only in frozen in-memory occurrences; this module provides no serializer, persistence, or logging path. `classify_package_ownership(raw_package, crypter, fingerprint)` is the narrow single-row twin used when the global inventory cannot be read: it parses one raw row through the same digest and answers three states, never two. A row that decodes to a mapping with a list `links` is readable, so `OWNERSHIP_NOT_OWNED` when none of those links carries the fingerprint and `OWNERSHIP_OWNED` when one does and `helper_package_is_candidate()` accepts the row. Everything else is `OWNERSHIP_UNKNOWN`: a missing, non-JSON, non-mapping, or link-less row proves nothing, and a row that carries the link but could never be handed out is not a mismatch either.
- `crypter_sweeps.py` is the version-two decision codec and imports nothing from Quasarr at module scope, so `crypter_cooldowns.py` may import it directly; only `migrate_legacy_record()` reaches back into the cooldown module, lazily. `helper_package_is_candidate(package_data)` is the one eligibility predicate shared by the candidate inventory and the helper handout - a readable mapping with both `title` and `password`, a non-empty list `links`, and no `disabled` key - so a frozen cohort can never contain a member the selector would refuse to offer.
- A version-two record is one of `sweeping`, cohort or migrated-legacy `cooldown`, `healthy`, or `individual`, with an exact key set and strict 32/64-lowercase-hex identifiers. Cohort members, `retest_members`, and `hold_fingerprints` are ascending unique lists bounded by `MAXIMUM_COHORT_SIZE`; accepted history is one newest result per fingerprint, also bounded by that maximum. Every accepted entry has exactly 14 fields (`offer_id`, `link_fingerprint`, `mode`, `outcome`, `state`, `instruction`, `accepted`, `cleared`, `hold_type`, `evidence_count`, `retry_after_epoch`, `sweep_tested`, `sweep_total`, `sweep_deadline_epoch`). `outcome` is the kind of report that produced the entry - `blocked`, `clear`, or `unknown` - and must agree with the response it stores (`cleared` implies `clear`, `accepted="unknown"` implies `unknown`, everything else `blocked`), so the route that may replay it is decided by data rather than guessed. `used_offer_ids` is ascending unique generation-wide history capped at `MAXIMUM_GENERATION_OFFER_IDS=1000`, and the whole encoded record is capped at 256 KiB. A cohort cooldown retains its original `opened_epoch`/`deadline_epoch`; every blocked member was tested inside that same 15-minute window under a unique used offer ID, and exactly one member owns the `cooldown` response. Records hold no URL, package ID, or release title.
- `decode_decision_record(value, now=...)` is total: an unreadable, foreign, legacy, future-schema, oversized (`MAXIMUM_COHORT_RECORD_BYTES`), deeply nested, or non-UTF-8-encodable surrogate row decodes as `None` instead of raising, so no persisted row can brick a read. It prunes an expired `cooldown`/`healthy`/`individual` decision (active while `now < deadline`, expired at equality) but never a `sweeping` record: an expired sweep still owns frozen evidence and only a transition may conclude it. `encode_decision_record()` re-validates, writes deterministic sorted compact JSON, raises `OverflowError` past the byte limit, and converts UTF-8 sizing failures to `ValueError`, so malformed text and oversized cohorts fail before mutation instead of escaping or committing dropped members.
- `migrate_legacy_record(value, now=...)` is lazy and pure, and the transition wrappers are its only writers. Any decoded mapping containing `schema_version` is versioned and can never enter legacy migration, regardless of that field's value or any legacy-shaped fields beside it; additive compatibility applies only to genuinely unversioned legacy rows. An old `observing` row is not a cohort and migrates to nothing, never to a cooldown, at any observation count; an old `cooldown` row keeps its exact `retry_after_epoch` and `legacy_evidence_count = max(1, surviving observations in the 15-minute window)` and gains no synthetic sweep, member, offer, or cohort-size field, and stays a marked legacy cooldown for the rest of its life.
- `CrypterCooldownService.crypter_projection(crypter)` is the one read that answers both halves of a defer projection: it retrieves the linkcrypter row once and returns the immutable `CrypterProjection(snapshot, decision)` pair derived from that same raw value and the same `now`, so a row transition can never combine a stale cooldown snapshot with a newer decision or hide a cooldown that started in between. A valid unexpired row is retrieved exactly once and never written; an unreadable or expired legacy row, and a structurally valid version-two row whose own window merely ended, take the lazy cleanup transaction, which re-derives the pair from the value current inside it. `is_decision_record()` is what separates those two: a clean version-two expiry deletes the row silently, while only genuinely unreadable state still warns. A past-deadline `sweeping` row is never deleted on a read - only a transition may conclude a sweep. Everything that needs both halves - `get_packages()` and `count_active_deferred_packages()` - goes through the pair, never through two reads. `snapshot()` is that pair's snapshot half and reads a version-two row through the codec into the existing snapshot key shape: a cooldown reports `state="cooldown"` with its retry deadline and cohort/legacy evidence count, a sweep reports `state="observing"`, and `healthy`/`individual` report `available` because they suppress global blocking.
- `crypter_sweeps.py` owns the pure transition layer: `expire_decision`, `prepare_decision`, `lease_next_offer`, `record_blocked`, `record_access`, `record_legacy_report`, `bypass_decision`, `stale_decision`, and frozen `Offer`. It touches no storage, settings, or clock and never edits a caller's record in place. Reports keep the fixed decision shape (`instruction`, `state`, `hold_type`, `accepted`, `cleared`, `evidence_count`, `retry_after_epoch`, `sweep_id`, `sweep_tested`, `sweep_total`, `sweep_deadline_epoch`, `events`). Accepted response history is separate from `live_offer`: a replay returns the stored verdict (state, instruction, accepted, cleared, hold type, evidence, retry) with the sweep identity and counters recomputed from the record that is current now - including the oversized `101` sentinel - and emits no event, while a superseded identity becomes stale. A replay is typed: `record_blocked` answers only an accepted `blocked` entry and `record_access` only an entry of the same access kind, so an accepted CLEAR or UNKNOWN presented to `/defer/` is stale rather than an empty instruction. Terminal cooldown, individual, UNKNOWN, retest, and healthy transitions retain the bounded history needed for those replays.
- `prepare_decision` opens only from available state, freezes 2 to 100 fingerprints, and uses generation-bound individual handling for one or oversized inventories. A sweep concludes at the earlier of its final report and deadline; pure expiry measures suppression from the original deadline. `lease_next_offer` never leases at or after the window deadline or over a live slot. Its optional `preferred_fingerprint` names the exact member the caller can hand out; a cohort-cooldown probe **requires** one and must name a frozen member, because a probe authorizes one package and a lease for a member that package does not contain could never be answered. Anything that cannot be leased exactly as named leases nothing, mints no identity, and leaves the record unchanged. Every minted ID is retained in `used_offer_ids`; an expired unaccepted lease gets a globally unused ID, collision retries stop after `MAXIMUM_OFFER_ID_ATTEMPTS`, and crossing the history cap raises before persistence. Sweep leases live on members; retest, individual, and cohort-cooldown probe leases use `live_offer`; migrated legacy cooldowns issue none. An `individual` window hands out each inventory fingerprint **at most once**: it leases the lowest one its `accepted_offers` do not already answer for, and leases nothing once every one of them is answered, so a dead inventory can never be replayed round after round. `individual(reason="cohort_oversized")` leases nothing at all, whatever the inventory looks like when it is read.
- Report validation order is generation, accepted-history replay, live unaccepted lease, then the situation transition. Wrong generations and expired, superseded, or never-accepted leases are non-destructive `stale`. A pending sweep holds; complete all-blocked evidence of at least five coherent members cools once; a smaller complete cohort or any terminal ambiguity becomes individual. Every BLOCKED report whose transition ends in a **holding** individual window (`cohort_too_small`, `sweep_expired`, `sweep_inconclusive`, `inventory_unavailable`) answers `hold`/`provisional` with that window's own `until_epoch` and retains the proven fingerprints in `hold_fingerprints`, never `legacy_failure`: an individual decision is not evidence for a linkcrypter-wide cooldown, but it is still a blocked container, and answering ordinary failure spends a helper attempt and eventually deletes the package. A concluding cohort retains exactly the members it proved `blocked` (an UNKNOWN member is not held); `expire_decision` carries the same set into the `sweep_expired` grace. Only a BLOCKED **retest** under `healthy` keeps ordinary failure, because there the linkcrypter is proven reachable. An inventory read failure permanently ends that generation as `individual(reason="inventory_unavailable")`, retains a hold only for the reporting fingerprint, and can never later recover into cooldown. `record_access` accepts CLEAR/UNKNOWN only: UNKNOWN is retained for replay without block events; a fresh CLEAR enters or refreshes healthy for 15 minutes and queues prior blocked fingerprints, while a duplicate accepted CLEAR replays its stored response without extending the window.
- `record_legacy_report()` is the version-one precedence rule and `observe()` uses it for every structurally valid version-two row, which is why a version-one report can no longer reach a global cooldown once a cohort decision exists. It never legacy-decodes or overwrites such a row: only an available linkcrypter may open or join `individual(legacy_v1_hold)` for 15 minutes, and a sweep, cooldown, healthy verdict, or differently-reasoned individual is reported but never changed. A row carrying no version-two decision keeps the exact legacy three-observation behavior, so incapable and version-one callers still receive their existing decisions.
- `record_version_one_report(crypter, package_id, link_fingerprint, reason_code)` is what a route uses: one `mutate_values` transaction over the linkcrypter row, the reporting protected row, and the outbox that records the observation, applies the pure `version_one_route_answer(decision, cohort_live=..., existing_defer=...)` mapping, and writes the package hold together. The precedence and the existing hold are read from the values current inside that transaction, so no caller may derive an answer or a write from an earlier read; a sweep installed in between answers `legacy_failure`/`none`/0 and writes nothing. It returns the recorded state and evidence plus the exact instruction, hold type, retry epoch, and whether the protected package was missing. `observe()` remains the record-only form and shares the same mutator.
- `healthy_from_legacy_success(record, now=..., generation_id_factory=...)` and its wrapper `CrypterCooldownService.record_legacy_success(crypter, *, package_id=None)` are the one safe path a version-one CLEAR may take into version-two state. A version-one report names no offer, so nothing is validated against a lease and nothing can be replayed: the decision is always replaced by a fresh 15-minute `healthy` window that queues every fingerprint the ending decision still held (blocked members, retained retest members, and fail-closed hold fingerprints). An existing generation is kept so its replay history stays addressable; a migrated legacy cooldown owns none and starts a fresh generation with empty history. The wrapper commits that window **first and alone**, and only afterwards runs `clear_crypter_generation_holds()` plus a compare-and-clear of the reporting package's own hold, both best effort with sanitized warnings. Ordering is the contract: a failed cleanup can never downgrade a proven acknowledgement, and a failed commit can never have released a hold that is still authorized. The reporting-package clear exists because a hold the version-one accumulator wrote carries no generation and the generation cleanup cannot name it; it still compares inside its own transaction and leaves a row a newer generation installed meanwhile untouched.
- `prepare_offer`, `record_cohort_blocked`, and `record_cohort_access` are thin atomic wrappers; `fail` mode is a pure bypass. Settings and package targets are resolved before one `DataBase.mutate_values` transaction commits the decision, affected protected rows, and outbox deltas. Ownership is resolved there too, because an offer identity proves a generation and never a container, and it is tri-state: while the inventory can be read it is decisive, so `OWNERSHIP_OWNED` makes the write set exactly the live occurrences of the reported link and any other reporting package is `OWNERSHIP_NOT_OWNED`; while it cannot, one narrow `classify_package_ownership()` row read may prove the reporter itself (write set exactly that package), disprove it, or answer `OWNERSHIP_UNKNOWN`, which a storage failure also answers after a warning naming only the two validated identifiers. `OWNERSHIP_NOT_OWNED` is a positive finding, so both cohort wrappers answer `_stale_report()` - a pure read that leaves the decision, every package, and the ledger byte-identical, not even pruning an expired window - and the offer stays unspent and replayable for whoever can prove it. `OWNERSHIP_UNKNOWN` is the absence of a finding, so a BLOCKED report and an UNKNOWN access still transition with an empty write set, which is what leaves the permanent `inventory_unavailable` taint reachable while writing no package row at all. A CLEAR under `OWNERSHIP_UNKNOWN` is stale instead: it is the one report that ends a generation for every package at once, and its only evidence is that the reporting container opened, so an unauthenticated package binding may neither clear nor taint. Record-size, used-ID, accepted-history, package-fingerprint, or ledger overflow raises inside that callback and rolls every row back. Generation holds bypass the legacy provisional budget and merge same-package fingerprints only within the same generation. A replay or stale result whose decision record is unchanged performs no package write, so an older accepted BLOCKED cannot resurrect metadata after CLEAR. Fresh CLEAR commits healthy first, then best-effort generation cleanup runs outside the transaction.
- Linkcrypter cooldown rows allow only `state="observing"|"cooldown"` and `reason_code="ip_block_suspected"`. Three distinct package IDs with three distinct SHA-256 link fingerprints inside one fixed 15-minute window create cooldown. Duplicate package/fingerprint evidence never changes an observation timestamp or advances that observation's provisional package retry deadline; each new distinct observation receives its own 15-minute provisional hold. Duplicate evidence also never extends `retry_after_epoch`. Expiry pruning makes `first_seen_epoch` the first surviving distinct observation; successful access deletes the row. Rows persist package IDs and fingerprints but never raw URLs.
- Package defer metadata lives only in protected-package JSON under `deferred` and has exactly two legal shapes: the unchanged six-key legacy block, and a nine-key version-two block adding `schema_version=2`, a 32-lowercase-hex `sweep_id`, and `link_fingerprints`, an ascending unique list of 1 to `MAXIMUM_COHORT_SIZE` 64-lowercase-hex values. Neither shape may carry a URL, title, or package ID. The short-lived singular-v2 shape is deliberately malformed and fail-closed: reads authorize no hold, warn through the existing sanitized boundary, and a later writer replaces it rather than guessing a migration. Same-generation cohort writes merge fingerprints and raise `OverflowError` before a 101st value so the enclosing decision/package/outbox transaction rolls back. `defer_package()` never mints a generation but carries an already-valid plural binding forward for the same linkcrypter; all package mutators preserve unrelated package fields and never create a missing package.
- `project_package_defer()` adds four read-only, identifier-free cohort fields to every projected block: zero defaults for tested/total/deadline/retest depth, or values from the current matching generation's validated decision snapshot. A stale generation and every legacy hold keep the zero defaults. Nothing copies a sweep ID, offer ID, fingerprint, URL, hostname, or title into the projection.
- `package_defer_is_active(deferred, decision_snapshot, *, now)` is the single hold authority and always reads the current decision. A generation hold is active for a matching cohort `cooldown` before its retry epoch, and for a matching `sweeping` record only until `sweep_deadline_epoch + SWEEP_WINDOW_SECONDS` - the instant `expire_decision` would have concluded it - because reading a record never transitions it and an abandoned sweep would otherwise hold its packages forever. Matching `individual(reason="legacy_v1_hold")` authorizes the whole generation; every other matching non-oversized individual reason authorizes only the intersection of `link_fingerprints` and the decision's `hold_fingerprints`, until `until_epoch`. `healthy`, `individual(reason="cohort_oversized")`, another or expired generation, malformed metadata, a marked legacy cooldown, or no readable decision authorizes no version-two hold. Legacy metadata keeps its own deadline without v2 state and only a marked legacy cooldown may extend it. `package_defer_covers_fingerprint()` checks membership in the plural list; legacy metadata covers the whole package.
- `crypter_decision(crypter)` is the read-only version-two decision projection (`None` for a legacy, missing, or expired row) and writes nothing. `compare_and_clear_package_defer(package_id, *, sweep_id)` removes a hold only while the row current inside its own transaction still carries that generation, so a newer generation written meanwhile survives a decision taken on an earlier read. `clear_crypter_generation_holds(crypter, *, sweep_id)` is its best-effort idempotent cohort-wide form: it enumerates and validates protected rows before any mutation (never scanning storage inside a mutation callback), clears rows matching that exact linkcrypter and sweep **plus every generationless version-one hold of that same linkcrypter** - a validated CLEAR is global evidence and nothing else can ever name those rows, so leaving them would let them fall back to their own stored deadline and resurrect once the health window ends - and returns `{"cleared": [...], "rejected": [{"package_id", "reason"}]}` in ascending package-ID order with the reasons `invalid_package_id`, `not_found`, `not_deferred`, `generation_mismatch`, and `storage_error`. A generationless hold is cleared only while the row current inside its own transaction still carries no `sweep_id`, so a generation-bound replacement written meanwhile survives. Best-effort is total, so no single usable row may end the cleanup: enumeration ignores entries that do not expose a two-element key/value pair with a string package ID because there is no package ID to report. For entries that do expose one, it decodes defensively and reports an unreadable payload as `not_deferred` while leaving it untouched (an out-of-contract ID still reports `invalid_package_id` first, and a readable row simply carrying no defer metadata is not reported), and each target is cleared in its own transaction, so an ordinary storage `Exception` there is reported as `storage_error` - the reason only, never the exception text - while later targets still run and every earlier clear stays committed. `BaseException` is never caught. It never changes the linkcrypter decision - physical cleanup only drops metadata the decision projection already invalidated.
- One-time probe state is package metadata only. `request_probe(package_ids)` returns `{"requested": [...], "rejected": [{"package_id", "reason"}]}` with the reasons `invalid_package_id`, `duplicate`, `not_found`, and `not_deferred`, and re-requesting a queued probe rewrites nothing. `consume_probe(package_id, crypter)` returns `True` only when it cleared a queued probe of that same crypter inside one transaction, so a crashed consumer cannot replay one probe. `delete_deferred_package(package_id)` deletes a protected row only while that same transaction still reads valid defer metadata and returns `deleted`/`not_found`/`not_deferred`. All three run through `_mutate_deferred_package()`, so no caller can act on package state it observed before the write.
- Linkcrypter transition accounting is an outbox, not a counter update: `observe()` and `consume_probe()` add their transitions to the single `crypter_events` row `pending` inside the very transaction that writes the record or spends the probe (`DataBase.mutate_values`). That row is owned by `CrypterCooldownService` and holds exactly the three integer fields `observations`, `cooldowns`, and `probes`; it can never contain a package ID, fingerprint, URL, or linkcrypter. Counts are cumulative and exact - they are never clamped, because a clamp commits a smaller number the counters can never catch up with. `MAXIMUM_CRYPTER_EVENT_COUNT` is only the largest value one row can hold and round-trip; exceeding it raises `OverflowError` inside the mutator, which rolls back the whole business transition rather than committing uncounted state. A malformed row is never deleted by an earlier read: it is re-decoded inside the flush transaction, so a valid row written since is counted instead of erased. Every malformed form self-heals - invalid JSON, booleans, negatives, wrong keys or types, integer literals with more digits than Python converts (a plain `ValueError`, not `JSONDecodeError`), and values nested past the recursion limit (a `RecursionError`, which is neither) - without ever blocking the observe/probe transition that carries the ledger. `StatsHelper.flush_crypter_events()` is the only drain: one `mutate_values()` transaction adds the pending counts to the three counter rows, clears the ledger together, and returns the committed totals, so an interrupted flush leaves everything pending and a repeated flush can never count twice. Consequences to preserve: a statistics failure can never change a helper decision, a crash between the transition and the flush loses nothing, and `record_success()`/CLEAR/deletion/expiry delete records but never the ledger.
- Legacy cooldown decoding validates every required record/observation field, accepts additive fields only when `schema_version` is absent, projects only known safe fields, and treats malformed rows as available after a concise warning containing only the normalized crypter key. Malformed covers every parse failure, including an integer literal with more digits than Python converts (a plain `ValueError`) and a value nested past the recursion limit (a `RecursionError`), so neither can escape a read. Missing and valid unexpired `snapshot`/`is_cooling`/`retry_after` reads use `retrieve()` only; malformed or expired cleanup uses one `mutate_value()` transaction that re-decodes version 2 before legacy, preserves and projects a concurrent valid v2 or legacy replacement, and deletes a future, malformed, or expired row only when that same value is still current.
- `crypter_cooldown_hours` is initialized and refreshed from `crypter_block_settings` by `storage.setup.crypter_blocks`. Missing/invalid values still use 24 hours and lower values are clamped to 24 so service callers remain safe before startup initialization or under malformed shared state.
- `crypter_blocks_deferred(shared_state)` is the single hold gate and owns `DEFAULT_CRYPTER_BLOCK_MODE`/`LEGACY_CRYPTER_BLOCK_MODE` (`storage.setup.crypter_blocks` imports them). It reads only the cached `crypter_block_mode`, never the settings table, and defers unless the value is exactly `fail`, so a missing, malformed, or differently-cased value keeps holds enforced. `fail` is a read gate only: it never clears, rewrites, or expires persisted cooldown or package defer state, so the mode can be flipped in either direction at runtime.
- Linkcrypter statistics are three cumulative transition counters plus one derived gauge. `observe()` decides `recorded` (a new distinct observation was appended) and `cooldown_started` (the record entered `cooldown` from a non-cooldown state) inside its own transaction and records both in the same transaction, so duplicate evidence and repeated reports count zero by construction; `crypter_probes` counts a probe only where `consume_probe()` actually spent one, in that same transaction, so a spent probe and its count can never disagree. `StatsHelper.crypter_transition_totals()` is the single source of those three numbers and never assembles them from two reads: it takes one `retrieve_values()` snapshot of the ledger plus the three counter rows, returns it unchanged while nothing is pending (so an idle statistics page still writes nothing), otherwise flushes and reports the totals that transaction committed, and on a write outage falls back to the snapshot it already holds. Reading statistics therefore never fails on a write problem, and a pending event is neither hidden nor - when another process flushes concurrently - counted twice. `deferred_packages` is never stored: `count_active_deferred_packages()` recounts protected rows whose projected defer is `active`, which is `0` in `fail` mode, drops by itself on CLEAR, deletion and lazy hold expiry, and can never go negative. Like every other projection it lazily prunes expired cooldown rows while reading.
- `TerminalOperationService` owns `sha256("sponsors-helper-terminal-v2\n" + package_id)` and the exact secret-free JSON row `{state, terminal_state, package_id, created_epoch, updated_epoch, package_removed, package_terminal, effect_state, failure_persisted, notification_state}` keyed by that digest. Phases advance in exactly this order and only forward: `(prepared, not_started) -> (prepared, attempting) -> (submitted, applied) -> (complete, applied)`; any other pair is an incoherent row that decodes to `None`, and a `(prepared, not_started)` row carrying any bookkeeping is incoherent too, because an operation that provably touched nothing cannot have counted or announced anything. Three row shapes decode: the current ten-key one, the eight-key one shipped before the bookkeeping existed, and the seven-key one shipped before `effect_state` existed. Both older shapes migrate their bookkeeping to `False`/`not_started` - they prove none of it - and are rewritten in the current shape at their next transition; any other key set is still rejected. Decoded records additionally carry `legacy_unproven`, which is never persisted (`_encode()` writes exactly `OPERATION_RECORD_KEYS`): it is `True` only for a seven-key row past `prepared`, whose artifacts carry no evidence at all, so neither their presence nor their absence says what that operation applied. A seven-key `prepared` row stays fully provable (nothing happened) and simply runs the current operation. Same package/state resumes, foreign reuse conflicts, and every decision re-reads inside `mutate_value()` without resolving storage or devices in the callback. `mark_effect_attempting()` is the durable phase a caller persists *before* its side effect and before any external call, because nothing outside the record can distinguish a crash while merely admitted from a crash after the effect. `record_failure(..., failed_target, failed_value, counter_targets)` is one `mutate_values()` over the operation row, the failed row and the named counters - every table of one Quasarr database lives in one file - so a counter can never answer for a row that was never written, a repeat writes and counts nothing, and it refuses entirely while the effect is still `not_started`. `mark_failure_persisted()` adopts a marked row an interrupted attempt of an older shape already committed and deliberately invents no counter. `mark_notification(target)` moves `not_started -> attempting -> recorded` and never backwards; `attempting` is written *before* the message is dispatched, because `update_release_notification()` is not idempotent (Telegram always sends a new message), so a retry that finds `attempting` closes it unsent rather than showing the operator a second one. `operation_evidence(record)` = `sha256(domain + package_id + created_epoch)` is what an artifact is marked with; it binds the lifecycle, so an artifact of an earlier life of the same package can never match and no marker ever has to be removed. `reopen_completed()` is the one transition that retires a record instead of advancing it: a package ID is derived from the release, so a package that is protected again reuses the identity of every life of it that already closed, and a complete record that can no longer describe that package is replaced - in one `mutate_value()`, never a delete followed by an open - by a freshly `prepared` one carrying none of its bookkeeping. The replacement's `created_epoch` is `max(now, retired + 1)`, so the next life opens strictly later and the two can never share their evidence even inside one second. Any phase other than `complete` resumes untouched (it may still own an unfinished side effect), a missing, foreign or unreadable row conflicts, and the caller owns the read of the protected package and the surrounding `operation_lock`. `submission_comment(package_id, evidence)` / `decode_submission_comment()` own the JDownloader comment: unmarked is the package ID itself (legacy, automatic and manual submissions), marked is `"<package_id> op:<64 hex>"`, and anything else is its own comment proving no operation. Two locks, never in the other order: `operation_lock(operation_id)` is per operation and keyed by a digest of the identity, so nothing a caller sends shapes a file name, and `exclusive()` validates first, then holds it while `begin()` re-reads the row and yields it - the caller must stay inside that block for its whole external side effect and the durable phases recording it. The module-level admission lock is capacity only, and it is taken inside an operation lock, never around one. At most 4096 rows are retained; `begin()` prunes complete rows at least seven days old on every request, before the lookup and the capacity decision, oldest-first/key-order with `delete_exact()` against the enumerated raw value, so prepared/submitted/unexpired complete rows and concurrent replacements survive while a package that was added again can open a different terminal state once its expired record is really gone. Before retention a conflicting state is still a conflict and the same state still replays. An existing operation resumes even at capacity. A stored row this build cannot decode - post-effect corruption, a future schema, a future phase - is neither absent nor a conflict: `prune_completed()` never reclaims it (deleting it would let the same identity open a fresh operation and repeat an effect that may already have been applied) and `begin()` answers the fourth outcome `UNREADABLE` with no record, leaving the raw value byte-identical and authorizing no side effect, counter, notification or removal. It still occupies its slot, so capacity stays bounded and an operator repairs that one identity. `count_by_state()` returns exactly the three fixed labels and no identifier.
- `crypter_cooldowns.py` lives under `providers/` because this package owns shared services; the path does not classify a linkcrypter as a provider.
- Response restoration contract for `page_dispatch`: restore via `response.headers.clear()` + `response.add_header(...)` over the saved headerlist so duplicate headers, status, and content type survive fallback unchanged.
- Classic-to-Carbon recovery link: `html_templates.render_centered_html()` appends exactly one `/ui/carbon?next=/` link to its existing footer list. Apart from that fixed footer fragment, wrapped Classic responses stay byte-identical to the pre-Carbon baseline captures; the separate unauthenticated login shell is unchanged.
- `utils.is_site_usable()` shares setup's *arr requirement check: a dual-category hostname needs either cached client; a movie-only or TV-only hostname needs its matching client.

- `quasarr.providers.static_assets` owns `_STATIC_ROOT`, `STATIC_MIME_TYPES`, `asset_url()`, `carbon_assets_available()`, and `setup_static_routes()`.
- `setup_static_routes()` must register exactly one `@app.get("/static/<filename:path>")` callback nested in that function and decorated with `@public_endpoint`; Bottle provides HEAD via GET.
- The route enforces safe relative paths, allowlisted suffixes, explicit MIME, `X-Content-Type-Options: nosniff`, immutable or `no-store` cache control, and clean 404 behavior.
