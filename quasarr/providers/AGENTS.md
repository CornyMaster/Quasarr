# quasarr/providers/ - Shared Services

## Purpose

The shared-services layer consumed by every other subsystem: cross-process state and the My.JDownloader device lifecycle, web server, logging, auth, per-source sessions, notifications, metadata lookups, statistics, Cloudflare/FlareSolverr helpers, HTML templating, and generic utils.

## Ownership

- `shared_state.py` - process-shared singleton (`set_state()` per process) and the JD device lifecycle (`get_device`, `run_device_request`, `set_device_settings`)
- `web_server.py` - WSGI wrapper; `serve_forever()` for the API, `serve_temporarily()` + `temp_server_success` flag for setup wizards
- `log.py` - loguru wrapper; context emoji from the caller's module name via `_context_replace`; per-context levels via `LOG`/`LOG_<CONTEXT>` env vars
- `auth.py` - route auth modes (`public_endpoint`/`require_api_key`/browser default), Bottle auth hook, startup audit
- `myjd_api.py` - vendored, modified My.JDownloader client (MIT, third-party) - keep modifications minimal
- `jd_cache.py` - `JDPackageCache`, valid for exactly one `get_packages()`/`delete_package()` call, never reused across requests
- `imdb_metadata.py` / `xem_metadata.py` - cached metadata chains: IMDb IDs resolve basic title/year/poster and title searches through the local Radarr or Sonarr client; localized titles use locale-specific IMDb release-info HTML and preserve that cache across Arr refreshes; German localized titles are transliterated once at this provider boundary for every source; `get_localized_title` takes an optional caller `deadline`, rechecked at each gate because the Arr refresh between them costs its own request, and then answers from cache only; the 60s FlareSolverr stage is also skipped when the direct IMDb request used the rest of the budget; TheXEM supplies season names
- `radarr_api.py` / `sonarr_api.py` - minimal clients cached in shared_state via `set_client`/`get_client`; IMDb and free-title lookup, IMDb→TMDB/TVDB resolution (`get_tmdb_id`/`get_tvdb_id`), plus library-feed seeds `get_wanted_imdb_ids` / `get_wanted_episodes` (wanted = missing + cutoff-unmet, missing first, capped at the passed `limit`, paging past filtered entries and stopping at an optional caller `deadline` and clamping each page request's timeout to what is left of it, since every page is its own *arr request - a caller timeout only ever tightens the client's own. `client.wanted()` returns `None` on a failed request so paging does not read it as the last page, and an optional `status` dict reports whether the walk completed, which callers persisting progress need; the movie helper skips not-yet-released titles and the episode helper skips not-yet-aired ones). All return safe empties when the client is unconfigured.
- `statistics.py` - DB-backed counters, constructed inline at call sites; also projects the derived `deferred_packages` gauge
- `version.py` - `__version__`, the single source of version truth
- `obfuscated.py` - generated obfuscated userscripts; consumed only by `api/captcha`; regenerated only through the private Quasarr-UserScripts generator repo
- `cloudflare.py` - challenge detection, thread-safe process-local 24-hour per-netloc FlareSolverr gating, lazy per-operation browser sessions, response wrappers, and get/post/session helpers
- `html_templates.py` / `html_images.py` - UI page shell, base64 image constants, and language-flag emoji/SVG fallback assets for setup UI
- `hostname_issues.py` - DB-backed source health tracker (`mark_/clear_/get_hostname_issue`)
- `crypter_cooldowns.py` - shared linkcrypter cooldown state machine; validates canonical protected-crypter keys, atomically records independent evidence, owns protected-package defer metadata and its generation binding, and exposes read-only availability snapshots
- `crypter_candidates.py` - pure bounded Filecrypt candidate inventory and the cross-repository normalized URL fingerprint contract; frozen occurrences retain decoded links only transiently
- `crypter_sweeps.py` - pure version-two linkcrypter decision codec: constants, strict record encode/decode, lazy legacy migration, the fixed read-only decision projection, and the shared helper-package candidate predicate
- `utils.py` - grab-bag: payload generate/parse, category resolvers, title matching (including shared date-numbering parsing/query/match/canonicalization), online-status checks, `download_package` (the JD linkgrabber submission)
- `sessions/` and `notifications/` - see Child DOX Index

## Local Contracts

- Each process calls `shared_state.set_state(dict, lock)` before use; read `shared_state.values[key]`, write `shared_state.update(key, value)`. `values["config"]`/`["database"]` hold the classes, not instances.
- All JDownloader access goes through `shared_state.get_device()` (blocks and retries forever with escalating backoff) or `run_device_request(name, fn, default)` (one reconnect+retry then the default on JD request errors - but its first attempt calls `get_device()` internally, so it too blocks until a device is connected). `TokenExpiredException`/`RequestTimeoutException`/`MYJDException` from `myjd_api` are the canonical JD error set.
- `generate_download_link` and `parse_payload` must stay in sync: urlsafe-base64 of exactly 6 pipe-separated fields (`title|url|size_mb|password|imdb_id|source_key`). This is the bridge between search results and the `/download/` endpoint.
- Auth: after `add_auth_hook`, every route defaults to browser auth; exceptions are marked with the decorators; `audit_route_auth_modes` raises at startup for unguarded API-prefixed routes; the API key lives in `Config('API')`.
- FlareSolverr: always check `utils.is_flaresolverr_available(shared_state)` first; when a FlareSolverr solution returns a userAgent, update shared_state `user_agent` globally.
- Optional Cloudflare fallback uses `LazyFlareSolverrSession`: an uncached netloc tries plain HTTP first; a real 403 or recognized challenge gates that netloc process-locally for 24 hours, after which same-host requests skip plain HTTP and go directly through FlareSolverr until the monotonic TTL expires. Gate access is thread-safe, first detection logs once at DEBUG, and cached requests stay quiet. Browser sessions remain lazy, are reused within one search/feed/download operation, receive at least the standard session timeout budget even when the plain request has a shorter search budget, and close from an outer `finally`. Solved JSON endpoints may arrive inside a browser-rendered `<pre>` wrapper, which `FlareSolverrResponse.json()` unwraps.
- IMDb metadata must not depend on an unofficial metadata API or GraphQL. Basic metadata comes from local Arr lookup responses. A localized title is guaranteed by accepting an Arr alternate title with an explicit matching ISO language code, the Arr `originalTitle` (or `title` when Sonarr omits it) when the record's `originalLanguage` names the requested language, a country-matched AKA row from IMDb release-info HTML or embedded page data, or IMDb `titleText` only when embedded request context proves the requested language, full localization, and disabled original-title preference. Arr lookups are checked before IMDb HTML; the HTML path serves English from the unprefixed default release-info path because IMDb 404s on `/en/`. Unproven `titleText` and instance-localized Arr display titles are not localized-title fallbacks. If no authoritative localized source exists, the lookup logs an error and returns no title. The cache preserves sanitized localized metadata, while `get_localized_title` returns one source-facing form: German umlauts and sharp S are transliterated on every successful return path, so individual sources must not add retries for spelling variants. Movie categories resolve stale or missing base metadata only through Radarr; TV categories resolve it only through Sonarr.
- DB tables owned here: `sessions`, `hostname_issues`, `imdb_metadata`, `imdb_searches`, `xem_all_names`, `xem_season_names`, `statistics`, `crypter_cooldowns`, `crypter_events`.
- Filecrypt candidate inventory accepts protected DB `(package_id, json_string)` rows, sorts canonical `PACKAGE_ID_PATTERN` packages by ID and stored link index, skips packages `helper_package_is_candidate()` rejects, and includes only links resolved by `resolve_protected_crypter_key(link) == "filecrypt"`. Full lowercase SHA-256 fingerprints deduplicate candidates globally while retaining every occurrence. Both capacity limits fail closed with the same empty `oversized=True` sentinel, returned immediately on discovery of unique fingerprint `MAXIMUM_COHORT_SIZE + 1` or occurrence `MAXIMUM_COHORT_OCCURRENCES + 1` and before any later link is inspected: truncating occurrences would leave a denominator that still looks complete. Raw links remain only in frozen in-memory occurrences; this module provides no serializer, persistence, or logging path.
- `crypter_sweeps.py` is the version-two decision codec and imports nothing from Quasarr at module scope, so `crypter_cooldowns.py` may import it directly; only `migrate_legacy_record()` reaches back into the cooldown module, lazily. `helper_package_is_candidate(package_data)` is the one eligibility predicate shared by the candidate inventory and the helper handout - a readable mapping with both `title` and `password`, a non-empty list `links`, and no `disabled` key - so a frozen cohort can never contain a member the selector would refuse to offer.
- A version-two record is one of `sweeping`, `cooldown` (cohort or the migrated `legacy_cooldown=True` variant), `healthy`, or `individual`, and each state has an exact key set, no missing and no additional key. IDs (`sweep_id`, `offer_id`, `generation_id`) are exactly 32 lowercase hexadecimal characters, link fingerprints exactly 64, epochs are non-negative non-boolean integers, and `result`/`response_instruction`/`mode`/`reason`/`reason_code` are closed enums. Cohort members and `retest_members` are ordered by ascending fingerprint, which is also what proves their uniqueness; a sweep carries 2 to `MAXIMUM_COHORT_SIZE` members and a cohort cooldown at least `MINIMUM_CONCLUSIVE_COHORT_SIZE` with `cohort_size == len(members)`. Every cohort-cooldown member is terminal `blocked` evidence with a positive tested epoch, a non-empty offer ID, an offer expiry no earlier than the test, and a replay instruction of `hold` or `cooldown`; exactly one member retains the transition's `cooldown` response. A sweep deadline is exactly one `SWEEP_WINDOW_SECONDS` after its `opened_epoch`. Records hold no URL, package ID, or release title.
- `decode_decision_record(value, now=...)` is total: an unreadable, foreign, legacy, future-schema, oversized (`MAXIMUM_COHORT_RECORD_BYTES`), deeply nested, or non-UTF-8-encodable surrogate row decodes as `None` instead of raising, so no persisted row can brick a read. It prunes an expired `cooldown`/`healthy`/`individual` decision (active while `now < deadline`, expired at equality) but never a `sweeping` record: an expired sweep still owns frozen evidence and only a transition may conclude it. `encode_decision_record()` re-validates, writes deterministic sorted compact JSON, raises `OverflowError` past the byte limit, and converts UTF-8 sizing failures to `ValueError`, so malformed text and oversized cohorts fail before mutation instead of escaping or committing dropped members.
- `migrate_legacy_record(value, now=...)` is lazy and pure - Task 4 owns the writes. Any decoded mapping containing `schema_version` is versioned and can never enter legacy migration, regardless of that field's value or any legacy-shaped fields beside it; additive compatibility applies only to genuinely unversioned legacy rows. An old `observing` row is not a cohort and migrates to nothing, never to a cooldown, at any observation count; an old `cooldown` row keeps its exact `retry_after_epoch` and `legacy_evidence_count = max(1, surviving observations in the 15-minute window)` and gains no synthetic sweep, member, offer, or cohort-size field.
- `CrypterCooldownService.crypter_projection(crypter)` is the one read that answers both halves of a defer projection: it retrieves the linkcrypter row once and returns the immutable `CrypterProjection(snapshot, decision)` pair derived from that same raw value and the same `now`, so a row transition can never combine a stale cooldown snapshot with a newer decision or hide a cooldown that started in between. A valid row is retrieved exactly once and never written; only an unreadable or expired legacy row takes the existing lazy cleanup transaction, which re-derives the pair from the value current inside it. Everything that needs both halves - `get_packages()` and `count_active_deferred_packages()` - goes through the pair, never through two reads. `snapshot()` is that pair's snapshot half and reads a version-two row through the codec into the existing snapshot key shape: a cooldown reports `state="cooldown"` with its retry deadline and cohort/legacy evidence count, a sweep reports `state="observing"`, and `healthy`/`individual` report `available` because they suppress global blocking. Version-two rows are not written anywhere yet, and observe/defer/API/statistics behavior is unchanged.
- Linkcrypter cooldown rows allow only `state="observing"|"cooldown"` and `reason_code="ip_block_suspected"`. Three distinct package IDs with three distinct SHA-256 link fingerprints inside one fixed 15-minute window create cooldown. Duplicate package/fingerprint evidence never changes an observation timestamp or advances that observation's provisional package retry deadline; each new distinct observation receives its own 15-minute provisional hold. Duplicate evidence also never extends `retry_after_epoch`. Expiry pruning makes `first_seen_epoch` the first surviving distinct observation; successful access deletes the row. Rows persist package IDs and fingerprints but never raw URLs.
- Package defer metadata lives only in the protected-package JSON under `deferred` and has exactly two legal shapes: the legacy block holding `crypter`, `reason_code`, `since_epoch`, `retry_after_epoch`, `probe_requested`, and `observation_holds`, and the version-two block adding exactly `schema_version` (the integer `2`), `sweep_id` (32 lowercase hex), and `link_fingerprint` (64 lowercase hex). Both are exact key sets - no missing and no additional key, `observation_holds` is exactly `0` or `1`, and neither may ever carry a raw URL. Any other shape, including a partial or future-versioned hybrid, is malformed: reads treat it as absent after a sanitized warning and the next `defer_package()` self-heals the block to the exact schema. `defer_package()`/`clear_package_defer()` mutate it through one `mutate_value()` transaction that preserves every other package field and never creates a missing package; `get_package_defer()` is read-only. `defer_package()` writes the legacy shape and never mints a generation, but it carries an existing `sweep_id`/`link_fingerprint` forward when it re-defers the same linkcrypter, because stripping the binding would leave a hold nothing can clear by generation; a hold of a different linkcrypter never inherits it. `observation_holds` is the provisional hold budget: a package receives at most one provisional hold and keeps that marker until it succeeds or is deleted, while a confirmed crypter cooldown (`observation_holds=0`) may still extend `retry_after_epoch`. `project_package_defer(deferred, snapshot, decision_snapshot=None)` merges stored metadata with a live snapshot into `state`, `evidence_count`, the effective `retry_after_epoch`, and `hold_type` (`crypter_cooldown`/`provisional`/`none`); it never writes. A protected row that cannot be parsed at all - invalid JSON, a non-object, nesting past the recursion limit (`RecursionError`), or an integer literal with more digits than Python converts (a plain `ValueError`) - reads as no package instead of raising, so one malformed row can never break a projection, a count, or a sweep-wide cleanup.
- A hold is authorized by the decision that is current on the read, never by a stored timestamp alone. `package_defer_is_active(deferred, decision_snapshot, *, now)` takes `crypter_decision()`'s projection or `None` and is the single authority: a version-two hold is active only inside a `sweeping` or cohort `cooldown` record of its own `sweep_id`, or an `individual` record with `reason="legacy_v1_hold"` whose `generation_id` matches, before its `until_epoch`. `healthy` deactivates it even while that record still names the same sweep, and another generation, an expired or differently-reasoned individual decision, a marked `legacy_cooldown`, or no decision at all invalidates it logically long before any row is physically removed - which is exactly why a cleanup that never ran can never revive it. A legacy hold predates generations: without a version-two decision it keeps its own deadline, only a marked `legacy_cooldown` extends it, and no other version-two state (least of all a cohort cooldown) may adopt it. Unreadable metadata and an unreadable decision prove nothing and hold nothing. `package_defer_covers_fingerprint(deferred, link_fingerprint)` is the fingerprint-level twin: a version-two hold speaks for exactly the tested link, so every occurrence of that fingerprint stays held while a different, never tested link in the same package does not, and a legacy hold covers the whole package.
- `crypter_decision(crypter)` is the read-only version-two decision projection (`None` for a legacy, missing, or expired row) and writes nothing. `compare_and_clear_package_defer(package_id, *, sweep_id)` removes a hold only while the row current inside its own transaction still carries that generation, so a newer generation written meanwhile survives a decision taken on an earlier read. `clear_crypter_generation_holds(crypter, *, sweep_id)` is its best-effort idempotent cohort-wide form: it enumerates and validates protected rows before any mutation (never scanning storage inside a mutation callback), clears only rows matching that exact linkcrypter and sweep, and returns `{"cleared": [...], "rejected": [{"package_id", "reason"}]}` in ascending package-ID order with the reasons `invalid_package_id`, `not_found`, `not_deferred`, `generation_mismatch`, and `storage_error`. Best-effort is total, so no single usable row may end the cleanup: enumeration ignores entries that do not expose a two-element key/value pair with a string package ID because there is no package ID to report. For entries that do expose one, it decodes defensively and reports an unreadable payload as `not_deferred` while leaving it untouched (an out-of-contract ID still reports `invalid_package_id` first, and a readable row simply carrying no defer metadata is not reported), and each target is cleared in its own transaction, so an ordinary storage `Exception` there is reported as `storage_error` - the reason only, never the exception text - while later targets still run and every earlier clear stays committed. `BaseException` is never caught. It never changes the linkcrypter decision - physical cleanup only drops metadata the decision projection already invalidated.
- One-time probe state is package metadata only. `request_probe(package_ids)` returns `{"requested": [...], "rejected": [{"package_id", "reason"}]}` with the reasons `invalid_package_id`, `duplicate`, `not_found`, and `not_deferred`, and re-requesting a queued probe rewrites nothing. `consume_probe(package_id, crypter)` returns `True` only when it cleared a queued probe of that same crypter inside one transaction, so a crashed consumer cannot replay one probe. `delete_deferred_package(package_id)` deletes a protected row only while that same transaction still reads valid defer metadata and returns `deleted`/`not_found`/`not_deferred`. All three run through `_mutate_deferred_package()`, so no caller can act on package state it observed before the write.
- Linkcrypter transition accounting is an outbox, not a counter update: `observe()` and `consume_probe()` add their transitions to the single `crypter_events` row `pending` inside the very transaction that writes the record or spends the probe (`DataBase.mutate_values`). That row is owned by `CrypterCooldownService` and holds exactly the three integer fields `observations`, `cooldowns`, and `probes`; it can never contain a package ID, fingerprint, URL, or linkcrypter. Counts are cumulative and exact - they are never clamped, because a clamp commits a smaller number the counters can never catch up with. `MAXIMUM_CRYPTER_EVENT_COUNT` is only the largest value one row can hold and round-trip; exceeding it raises `OverflowError` inside the mutator, which rolls back the whole business transition rather than committing uncounted state. A malformed row is never deleted by an earlier read: it is re-decoded inside the flush transaction, so a valid row written since is counted instead of erased. Every malformed form self-heals - invalid JSON, booleans, negatives, wrong keys or types, integer literals with more digits than Python converts (a plain `ValueError`, not `JSONDecodeError`), and values nested past the recursion limit (a `RecursionError`, which is neither) - without ever blocking the observe/probe transition that carries the ledger. `StatsHelper.flush_crypter_events()` is the only drain: one `mutate_values()` transaction adds the pending counts to the three counter rows, clears the ledger together, and returns the committed totals, so an interrupted flush leaves everything pending and a repeated flush can never count twice. Consequences to preserve: a statistics failure can never change a helper decision, a crash between the transition and the flush loses nothing, and `record_success()`/CLEAR/deletion/expiry delete records but never the ledger.
- Legacy cooldown decoding validates every required record/observation field, accepts additive fields only when `schema_version` is absent, projects only known safe fields, and treats malformed rows as available after a concise warning containing only the normalized crypter key. Malformed covers every parse failure, including an integer literal with more digits than Python converts (a plain `ValueError`) and a value nested past the recursion limit (a `RecursionError`), so neither can escape a read. Missing and valid unexpired `snapshot`/`is_cooling`/`retry_after` reads use `retrieve()` only; malformed or expired cleanup uses one `mutate_value()` transaction that re-decodes version 2 before legacy, preserves and projects a concurrent valid v2 or legacy replacement, and deletes a future, malformed, or expired row only when that same value is still current.
- `crypter_cooldown_hours` is initialized and refreshed from `crypter_block_settings` by `storage.setup.crypter_blocks`. Missing/invalid values still use 24 hours and lower values are clamped to 24 so service callers remain safe before startup initialization or under malformed shared state.
- `crypter_blocks_deferred(shared_state)` is the single hold gate and owns `DEFAULT_CRYPTER_BLOCK_MODE`/`LEGACY_CRYPTER_BLOCK_MODE` (`storage.setup.crypter_blocks` imports them). It reads only the cached `crypter_block_mode`, never the settings table, and defers unless the value is exactly `fail`, so a missing, malformed, or differently-cased value keeps holds enforced. `fail` is a read gate only: it never clears, rewrites, or expires persisted cooldown or package defer state, so the mode can be flipped in either direction at runtime.
- Linkcrypter statistics are three cumulative transition counters plus one derived gauge. `observe()` decides `recorded` (a new distinct observation was appended) and `cooldown_started` (the record entered `cooldown` from a non-cooldown state) inside its own transaction and records both in the same transaction, so duplicate evidence and repeated reports count zero by construction; `crypter_probes` counts a probe only where `consume_probe()` actually spent one, in that same transaction, so a spent probe and its count can never disagree. `StatsHelper.crypter_transition_totals()` is the single source of those three numbers and never assembles them from two reads: it takes one `retrieve_values()` snapshot of the ledger plus the three counter rows, returns it unchanged while nothing is pending (so an idle statistics page still writes nothing), otherwise flushes and reports the totals that transaction committed, and on a write outage falls back to the snapshot it already holds. Reading statistics therefore never fails on a write problem, and a pending event is neither hidden nor - when another process flushes concurrently - counted twice. `deferred_packages` is never stored: `count_active_deferred_packages()` recounts protected rows whose projected defer is `active`, which is `0` in `fail` mode, drops by itself on CLEAR, deletion and lazy hold expiry, and can never go negative. Like every other projection it lazily prunes expired cooldown rows while reading.
- `crypter_cooldowns.py` lives under `providers/` because this package owns shared services; the path does not classify a linkcrypter as a provider.
- `utils.is_site_usable()` shares setup's *arr requirement check: a dual-category hostname needs either cached client; a movie-only or TV-only hostname needs its matching client.

## Work Guidance

- `log.py` and `auth.py` have import-time side effects (logger init, env reads).
- Circular imports are avoided with lazy imports inside functions - follow that pattern when a module needs storage at import time.
- `obfuscated.py` (2.2MB) and `html_images.py` have extremely long lines - grep them; do not Read whole, do not deobfuscate or regenerate the JS blobs, and never add source hostnames to them.
- New shared service: accept `shared_state` as a parameter (don't import it directly), use constants for timeouts, add a context-emoji entry to `log._context_replace`.
- Failure handling is log-and-return-default rather than raising; exceptions are reserved for programmer errors.
